## 중단·관측 한계

실행하지 않은 단계: 

실행기 중단 사유: phase_failed_book-400

CPU는 Prometheus 1분 평균 표본이며 1초 SSH 표본도 따로 보존했다. 15/30초 관측 사이의 순간 포화·잠금은 놓칠 수 있다. Mongo는 exporter 없이 SSH 표본이다. 앱 DB 풀 획득 대기는 미계측이며 전체 연결 한도 미도달이 풀 대기 부재를 증명하지 않는다. FastAPI Prometheus는 수집 워커 기준이므로 전체 요청은 Locust·Nginx 로그를 우선한다.

신규 event_daily 타이머·완료/크롤러 타이머를 끄지 않았다. timer 기록에서 본 측정과 겹친 실행이 있는지 확인한다. 계정 준비/로그인·cleanup은 본 측정 밖이며 DB 최종 행 수는 준비/워밍업/본 측정/정리를 모두 포함한다.

## 판정·정합성·공유 작업 이력

- 100명: 준비/워밍업/본 측정/종료에서 오류0, 예약201 p95 64.93ms. 200명: 오류0이지만 예약201 p95 1,022.31ms로 500ms 가이드 미달.
- 400명 목표: 로그인503 2건, 워밍업503 18건(예약7·취소6·내역조회5). 본 측정 5xx/전송 오류는0이지만 신규 생성 기대201 대신 기존 예약200을 91번 받았다. 워밍업22·종료5건까지 포함해 이 재응답은118건이다. **HTTP200 자체가 API 버그라는 뜻은 아니다.** 선행 취소 실패 후 같은 칸을 재시도한 정상 멱등 응답이므로 새 INSERT 처리량으로 세지 않았다.
- 로그인 실패로 본 측정의 실제 사용자는398명이었다(CSV 종료 경계 1초 제외 확인). 이 구간은 정상400명 쓰기 용량을 검증한 결과가 아니다. 오류로 후속 증량을 중단했다. 실패 후 해당 VU의 정리/정지 없이 기존 예약을 반복한 시나리오 한계도 있으므로 다음 재시험에서는 워밍업 오류를 차단하고 실패 계정을 격리해야 한다.
- 최종 계정400개 소유 예약/모의결제10,080건이 primary·replica에서 모두 cancelled/refunded, 합성 표시10,080/10,080, 잔여 슬롯0으로 일치했다. 준비·워밍업·본 측정·종료의 총합이며 본 측정201 수와 다르다.
- Mongo user.user_id는 문자열이다. 문자열 기준으로 reservation_complete10,080 + reservation_cancel_complete10,080 = 합성 이벤트20,160건을 확인했다. 초기 숫자형 필터의0은 집계 필터 오류였으며 문서 타입 확인 후 정정했다. 데이터 누락이 아니다. event_daily는19:20:00~01 집계 성공, 현재4,005행. 이 타이머는 이번 본 측정 세 구간과 겹치지 않았다.
- API1/2 Uvicorn 동시성 초과 경고0, HAProxy DOWN/UP 전환0이었다. 이번503은 애플리케이션 JSON SERVICE_UNAVAILABLE이며, 풀 timeout/접속 오류 세부 유형이 로그에 없어 최초 원인을 확정하지 않는다. DB전체연결한도151은 유지했다. 풀 대기는 미계측이다.
- 실제 conf.d·앱 파일 지문이 전후 같고 서비스 시작도18:53대로 시험 전이었다. 다만 작업판 사고 이력에 **Claude가19:13 Codex 잠금을 무시하고 mon 대시보드를 교체하고 잠금을 삭제,19:15 owner만 복구했다**고 기록돼 있다. 시험 종료 시 runner 메타데이터가 없어 종료 처리 예외가 났다. 기록/계정 정리는 보존됐지만 완전히 격리된 실험이라고 주장하지 않는다. 신규 UI 수정은 이 기록을 보존한 뒤 별도로 반영한다.
- CPU/RAM/디스크 표본상 지속 포화는 관측되지 않았다. 400명 목표 구간 API1/2 CPU 1분 평균 최고64.91/64.36%, RAM41.68/42.00%, 디스크busy0.05/0.05%였다. DB연결 최고15/14, 잠금·복제지연 표본0이다. 순간 피크·풀 대기 부재를 보장하지 않는다.
- 200명의 지연이400목표보다 높아도 최적화 효과를 뜻하지 않는다. 실제 인원/상태가 다르고 한 번의 실행이다. 동일배포 읽기 재확인·반복 측정 및 앱 풀/작업 대기 계측을 먼저 검토한다. 신규 하드웨어 증설이나 동시성 상향은 아직 하지 않았다.
