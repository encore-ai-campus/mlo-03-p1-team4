## 작업 시작·종료 규칙

1. **시작 전 서버 작업판을 다시 읽는다.** 작업 ID·담당·서버/파일/서비스·변경 명령·시작 시각(KST)·예상 종료·검증 방법·되돌릴 방법을 아래 상세 칸에 쓴다.
2. 같은 VM·서비스·Terraform state·공유 앱 디렉터리를 다른 담당이 사용 중이면 변경하지 않는다. 로컬 문서 작성은 가능하다. 작업판에 적혀 있는 진행 중 예약도 존중한다.
3. 공용 문서 편집은 짧게 직렬화한다. 아래 `flock`은 **MD 편집 중 충돌을 줄이는 잠금**이며 서버 작업 자체를 예약하는 잠금은 아니다.
4. 배포·재시작·VM 변경·부하 실행은 전역 작업 잠금 디렉터리를 원자적으로 선점한 에이전트 한 명만 수행한다. 기존 진행 중 예약이 있으면 잠금이 없더라도 먼저 담당자와 인계한다.
5. 장시간 작업은 5분마다 또는 단계 전환 때 현재 단계와 마지막 확인 시각을 적는다. 오래된 표시만으로 잠금·예약을 강제로 지우지 않는다.
6. 부하 시험 중에는 다른 에이전트가 배포·설정 변경·재시작·이미지 빌드·추가 부하를 하지 않는다. Grafana 조회처럼 가벼운 관측만 하고, 로그 대량 추출도 종료 뒤에 한다.
7. 종료 시 결과·실패·남은 작업·산출물 위치·검증 시각을 기록하고 **자기가 소유한** 작업 잠금만 해제한다. 실패한 작업도 행을 지우지 않는다.
8. 에이전트가 이 규칙을 읽지 않으면 MD만으로 동시 작업을 강제 차단할 수 없다. 처음 참여하는 Claude/Codex에 아래 전달문을 준다.

### 공용 MD 읽기·편집 (WSL 셸)

```bash
cd /home/playdata/spacecube109
cat SERVER_WORK_BOARD.md
# nano가 있는 경우. 다른 편집기를 쓰더라도 같은 잠금 파일을 사용한다.
flock -w 5 .server-work-board.edit.lock nano SERVER_WORK_BOARD.md
```

스크립트로 수정할 때도 같은 편집 잠금을 잡은 뒤 파일을 다시 읽고 **자기 행·상세 칸만** 바꾼다. 임시 파일 작성 후 같은 파일시스템에서 원자적으로 교체한다. 다른 에이전트의 상태를 과거 내용으로 되돌리지 않는다.

### 서버 변경·부하 실행 선점 (WSL 셸)

```bash
cd /home/playdata/spacecube109
mkdir .server-operation.lock
# 성공해도 MD에 다른 진행 중 예약이 있으면 실행하지 말고 인계를 확인한다.
# 자신의 작업 ID·담당·시작 시각을 MD에 기록한 뒤 승인된 작업을 수행한다.
# 완료/실패를 MD에 기록한 후 자신이 만든 빈 디렉터리만 해제한다.
rmdir .server-operation.lock
```

위 코드는 순서 안내다. 시작과 종료 사이에 실제 작업을 넣으며, 잠금을 얻지 못한 상태에서 `rmdir`를 실행하지 않는다. Terraform 자체의 state lock은 유지하고 `-lock=false`로 우회하지 않는다.

## Claude / Codex에 전달할 문구

> 서버 작업 전 `ssh playdata`로 접속해서 `/home/playdata/spacecube109/SERVER_WORK_BOARD.md`를 먼저 읽어 줘. 그 파일을 공용 기준으로 쓰고 본인 작업 ID·대상 VM/IP·파일·시작 시각을 등록해 줘. 다른 에이전트가 같은 대상에서 작업 중이면 변경이나 부하를 실행하지 말고 인계 대기로 적어 줘. 서버 변경·부하 실행은 `/home/playdata/spacecube109/.server-operation.lock`을 `mkdir`로 선점한 뒤 수행하고, 완료·검증 결과를 기록한 다음 자기 잠금만 해제해 줘. 비밀번호·토큰·개인키는 문서에 적지 마.
