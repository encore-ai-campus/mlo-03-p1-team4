# 공간대여 예약 시스템 — 프론트 현황 (팀 공유용)

2026-11-03 · FE · 확정안 FE-1~9 반영

화면 7개를 11-03 계약에 맞췄습니다. Vue·Noto Sans KR·기존 CSS 토큰을 유지했습니다. 백엔드 없이 목업으로 실행하며 실제 API·DB와 연결한 결과는 아닙니다.

## 실행

`frontend/`에서 `npm install` 후 `npm run dev`. 주소는 http://localhost:5173, 공통 UI 모음은 `/ui`입니다.

- 목업 로그인: `study@example.com` + 아무 비밀번호 8자 이상.
- 충돌 체험: `/venues/1`에서 21시를 선택하고 결제하면 409가 나며 다른 칸을 고를 수 있습니다.
- 새로고침하면 메모리 목업의 예약·회원·토큰이 초기화됩니다. 다시 로그인해야 합니다.
- 결제는 `transfer`·`card`·`phone` 모의 결제입니다.

## API 연결 지점

- 모든 호출은 `frontend/src/api/`에서 합니다. 기준은 `백엔드_A_회원_후기_이벤트.md`·`백엔드_B_공간_예약_결제_크롤링.md` 5절입니다.
- 모든 요청에 같은 `X-Session-Id`, 회원 요청에 Bearer 토큰을 붙입니다. 60분 만료(401)는 로그아웃 후 선택값을 유지한 로그인 화면으로 이동합니다.
- 예약 응답 200도 성공이며 409의 `slots`·`mine`을 처리합니다. 목업은 중복 요청·내 예약 충돌·지난 예약을 재현합니다. 실제 DB 트랜잭션·50건 동시성은 B·DB 통합 검증이 필요합니다.
- `NETWORK_ERROR`·`INTERNAL_ERROR`는 다시 불러오기(500이면 토스트에 오류 번호 `request_id`도 표시), `METHOD_NOT_ALLOWED`는 토스트, `SERVICE_UNAVAILABLE`은 전체 안내와 30초 뒤 조회 재시도를 제공합니다. 결제를 자동 재전송하지 않습니다.
- 이벤트는 프론트 허용 9종만 전송하며 공간은 최상위 `venue_id`에 둡니다. 목업은 외부 전송·콘솔 출력을 하지 않습니다. 이벤트 실패는 예약 화면을 중단하지 않습니다.
- 실제 서버 준비 후 `VITE_USE_MOCK=false`로 전환해 `/api` 연결을 검증합니다. 현재 프록시 대상은 `http://localhost:8000`입니다.

## 검증과 남은 일

검증 명령·최종 결과는 `docs/기록/작업_2026-11-03_프론트_FE반영.md`에 기록합니다. 린트·단위·빌드와 데스크톱 1280/모바일 375 화면 흐름·접근성·움직임을 검사합니다. 이 PC는 설치된 Chrome을 사용합니다(`PLAYWRIGHT_CHANNEL=chrome`).
