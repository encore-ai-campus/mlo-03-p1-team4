전역 SELECT, 쓰기·DDL·SUPER·복제 관리 권한을 주지 않았다. 자격증명은 각 DB 안에서 생성해 보호 파일에만 보관했으며 공유 문서·Git·명령행 인자에 넣지 않았다. 로컬 모니터링 계정 생성은 복제 binlog에 전파하지 않고 각 DB에서 별도로 처리했다.

mysqld 활성 collector는 실제 `mysql_exporter_collector_success=1`로 확인한 다음 9개다: global_status, global_variables, slave_status, info_schema.tables(spacecube만), info_schema.innodb_metrics, info_schema.processlist(원본 host 집계 포함), 기본 활성 innodb_cmp, innodb_cmpmem, query_response_time. 마지막 세 개가 활성이라는 사실이 MariaDB에 별도 통계 플러그인을 설치/활성화했다는 뜻은 아니다. node exporter는 기본 OS collector와 textfile을 사용하며 CPU·meminfo·filesystem·diskstats·연결 집계 시계열을 확인했다.

설치된 0.15.0에서는 `--mysqld.address=unix://...` CLI 값이 host:port 파싱 오류를 냈다. **socket은 보호된 my.cnf의 socket 항목으로 지정**해 해결했다. 최신 main README의 문법을 구버전에 그대로 적용하지 않는다. [해당 버전 공식 코드](https://github.com/prometheus/mysqld_exporter/blob/v0.15.0/config/config.go) · [MariaDB REPLICA MONITOR 설명](https://mariadb.com/docs/server/reference/sql-statements/administrative-sql-statements/show/show-replica-status).

Prometheus는 기존 15개에 DB node 2·mysqld 2를 더해 **19/19 UP**을 확인했다. MongoDB exporter를 추가한 것은 아니다. Mongo 자원은 시험기의 SSH 표본으로 별도 기록한다. Grafana는 전체 11개 대시보드에서 DB 연결·대기로 이동할 수 있고, MariaDB 15패널·연결/대기 8패널의 쿼리를 실제 시계열로 검사했다. 긴 PromQL/라벨을 상단 숫자 카드에서 숨겼다.

## 5. MongoDB 현재 저장 구조

MongoDB는 **8.0.34**(팀 OVA)이며 인증이 켜져 있다. 이전 4대 시험에서 제외됐던 것과 달리 지금은 API와 연결돼 있다. DB/컬렉션은 다음처럼 구분한다.

| 저장소 | 용도·현재 확인 |
| --- | --- |
| space_rental_analytics.events | 원천 이벤트, event_id 고유 인덱스, received_at TTL 365일(31536000초) |
| space_rental_analytics.event_daily | 일 집계. date/event_type/venue_id/is_synthetic 고유 인덱스, TTL 없음 |
| crawl.crawl_raw | 크롤링 추출값. source_site/source_id 고유 인덱스, 상태/유형 인덱스 |

events 검증 규칙은 strict/error이며 event_id·schema_version·event_name·occurred_at·received_at·user·site·acquisition·page·navigation·products·properties·is_synthetic·server 필수 조건을 확인했다. validator의 최상위 $jsonSchema만 읽어 required=null인 것으로 오해하지 않도록 중첩 $and도 검사했다.

원천은 `schema_version=1`, `event_name`, `occurred_at`, `received_at`, `user`, `site`, `acquisition`, `page`, `navigation`, `products`, `properties` 구조다. **기존 user_events·event_type·ts·payload 평면 원천 스키마와 구분**한다. 상세 필드·허용 행동은 [속성 정리 v1](db/events_event_daily_컬렉션_속성정리_v1.md)을 따른다.

프론트 이벤트 요청은 OpenAPI에서 일부 문맥이 optional로 보여도 서비스 검증에서는 schema_version=1 및 user·site·acquisition·page·navigation의 유효한 문맥이 필요하다. user.session_id는 batch.session_id와 같아야 한다. 상품 이벤트는 products에 존재하는 공간의 product_id 하나를 보내고 상품 스냅샷은 서버가 만든다. page_view에는 상품을 붙이지 않는다.

event_daily의 **event_type·venue_id는 현재 집계 컬렉션의 의도된 필드 이름**이다. 원천 `events.event_name`→집계 `event_type`, `products[].product_id`→`venue_id`로 변환하며 원천과 이름이 다르다고 인덱스를 임의 변경하지 않는다. 일 집계가 0건인 것과 원천 이벤트가 안 쌓이는 것은 다르다. 집계 구현·cron은 별도 확인한다.

수신 이벤트는 events.log에 먼저 남기고 Alloy→Loki로 전달하며 MongoDB 쓰기는 응답 뒤 수행한다. 202/accepted는 Mongo 저장 완료 증명이 아니다. API 재전송 중복 보장 범위는 #17의 별도 합의 대상이며 event_id 인덱스만으로 모든 API 재전송이 제거된다고 설명하지 않는다. Mongo VM의 ufw 미설정은 기존 인계의 남은 작업이며 이번 MariaDB exporter 작업에서 변경하지 않았다.
