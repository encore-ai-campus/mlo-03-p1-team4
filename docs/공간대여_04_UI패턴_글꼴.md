### 움직임 규칙

기준: [emilkowalski/skills](https://github.com/emilkowalski/skills)의 `review-animations` (2026-11-02 점검에서 맞춤).

- 시간 토큰(`tokens.css`): 툴팁 125ms · 빠름 150ms(호버·눌림·닫힘) · 보통 250ms(탭·창·드로어 열림) · 등장 300ms(리빌·스태거). UI는 300ms를 넘기지 않고, **닫힘은 열림보다 빠르게**(창·드로어 열림 250 → 닫힘 150).
- 곡선: `--ease-out` = `cubic-bezier(0.23, 1, 0.32, 1)`(기본), 드로어 열림은 `--ease-drawer` = `cubic-bezier(0.32, 0.72, 0, 1)`. **`ease-in`은 쓰지 않는다**(처음이 느려 굼떠 보임). 계속 도는 것(스켈레톤 빛 띠)은 `linear`.
- 눌림은 `scale(0.95~0.97)`. 자주 누르는 시간 칸은 0.97로 약하게.
- 나타나는 것은 `scale(0)`에서 시작하지 않는다(0.97~0.98 + 투명도). 툴팁은 버튼 쪽에서 커지고(`--reka-tooltip-content-transform-origin`), 이어서 여는 툴팁은 움직임 없이 바로. 창은 가운데에서.
- 빠르게 껐다 켜는 것(찜 하트 등)은 처음부터 다시 도는 keyframe 대신 transition.
- reka 창·드로어의 닫힘 키프레임은 열림과 **다른 이름**이어야 한다(같으면 움직임 없이 바로 사라짐).
- 한 화면에서 동시에 움직이는 것은 1~2개까지.
- `transform`과 `opacity`만 움직인다. 예외: 아코디언 높이(reka 방식).
- `prefers-reduced-motion: reduce`면 **없애지 않고 적고 부드럽게**: 이동·크기 변화는 흐려짐으로 바꾸고(창·드로어·툴팁·카드 등장·결제 완료), 호버 들림·탭 밑줄 이동·아코디언 높이·스켈레톤 빛 띠는 끈다. 지연과 부드러운 스크롤은 `base.css`에서 전역으로 끄고, JS 스크롤은 `utils/motion.js`의 `scrollBehavior()`, 스크롤 리빌은 `usePreferredReducedMotion`.
- 지켜지는지는 `frontend/e2e/motion.spec.js`가 본다.

## UX 법칙 5가지 적용 (11-03)

화면을 고칠 때 아래 다섯 법칙을 기준으로 봅니다. '지금'은 11-01 코드를 읽어 확인한 상태이고, '바꿀 것'은 `프론트_변경목록_11-03.md`의 예약 흐름 개편과 같이 합니다. 출처는 [Laws of UX](https://lawsofux.com/)의 각 항목입니다.

| 법칙 | 뜻 (출처) | 우리 규칙 |
| --- | --- | --- |
| 힉의 법칙 | 고를 것이 많고 복잡할수록 결정이 느려진다 (Hick·Hyman, 1952) | 한 번에 보이는 선택지는 7개 안팎. 많으면 추천·자주 쓰는 것을 먼저 보이고 나머지는 '더 보기'. 긴 작업은 단계로 나눈다 |
| 피츠의 법칙 | 목표를 누르는 시간은 거리와 크기에 달렸다 (Fitts, 1954) | 누르는 것은 44px 이상(`--tap`), 붙은 버튼 사이 8px 이상. 주 행동 버튼은 손이 닿는 곳(폰은 화면 아래 고정 바, 데스크톱은 요약 바로 옆)에 넓게 |
| 제이콥의 법칙 | 사람들은 다른 사이트에서 익힌 방식대로 쓰기를 기대한다 (Jakob Nielsen) | 국내 공간대여·예약 사이트의 익숙한 순서(날짜 → 시간 칸 → 인원 → 금액 요약 → 결제)를 바꾸지 않는다. 로고는 왼쪽 위·홈, 내 예약은 오른쪽 위, 결제수단은 카드가 먼저 |
| 근접성의 법칙 | 가까이 있는 것은 한 묶음으로 보인다 (게슈탈트) | 관련된 것끼리 붙이고 묶음 사이를 띄운다(묶음 안 8~12px, 묶음 사이 24px 이상). 오류 문구는 그 칸 바로 아래, 금액은 결제 버튼 바로 위, 칸 범례는 시간표 바로 위 |
| 폰 레스토프 효과 | 비슷한 것들 사이에서 튀는 하나가 기억된다 (von Restorff, 1933) | 화면(같이 보이는 영역)마다 채운 강조 버튼(`primary`)은 하나. 강조를 색만으로 하지 않고 모양·글자도 바꾼다. 움직임으로 튀게 하지 않는다(움직임 줄이기 존중) |

| 메인 | 힉·레스토프 | 히어로 검색 카드 + 유형 벤토 + NEW + 카드 + 차트 + 후기 | 첫 화면의 주 행동은 '빈 공간 찾기' 하나. 벤토·NEW 카드는 강조 색을 나눠 쓰지 않는다(NEW 배지 하나만 튐) |

### 검사

- `e2e`: 화면마다 보이는 영역의 채운 버튼 수 ≤ 1, 누르는 요소 44px 이상, 붙은 버튼 간격 8px 이상을 확인하는 테스트를 `a11y.spec.js`에 더한다(개편 때).
- 디자인 점검은 설치한 스킬로: 화면 점검 `impeccable`(`/impeccable critique`·`audit`), 움직임 점검 `design-motion-principles`(audit 모드). `hallmark`·`design-taste-frontend`는 자기 화풍을 새로 정하는 스킬이라 이미 정한 토큰(`tokens.css`)과 부딪힌다. 새 화면을 처음부터 만들 때만, 하나만 쓴다. 예외: 11-05 강사님 코멘트로 `design-taste-frontend`를 기존 화면 전체에 한 번 적용했다(보라 → 올리브 `#38450f` on 뼈색 `#ecebe7`, 알약 배지·그림자·빗금 없앰, 반경 4~6px). 색 값은 `tokens.css`가 기준이다.

## 접근성 기준 (모든 화면)

- 글자 대비 4.5:1 이상, 누를 수 있는 영역 44×44px 이상, 포커스 표시를 지우지 않음
- 아이콘만 있는 버튼에는 `aria-label`, 장식용 그림은 `aria-hidden`
- 색만으로 상태를 구분하지 않음(마감 칸은 빗금 + '마감' 글자)
- 아이콘은 lucide 선 아이콘, 이모지를 아이콘으로 쓰지 않음

## 글꼴

후보 5종 모두 OFL입니다. 원본·설치·웹 변환은 `design/fonts/README.md`, 시안은 캔버스 '글꼴 시안' 페이지에 있습니다.

- **결정: Noto Sans KR (11-01).** 시안 비교 후 팀이 골랐어요. 웹 용량이 가장 작고(324KB) 숫자가 기본 고정폭이라 시간표·가격 자릿수가 잘 맞습니다. 나머지 4종의 파일과 `@font-face`는 비교용으로 남겨 둡니다.
- **숫자 정렬:** 시간표·가격·카운트다운에는 `font-variant-numeric: tabular-nums`(`.num`)를 줍니다. Noto Sans KR은 숫자가 기본 고정폭이지만, 나중에 글꼴을 바꿔도 자릿수가 맞도록 그대로 둡니다.
- **글꼴 바꾸기:** 프론트 `src/styles/fonts.css`의 `--font-sans` 한 줄만 바꾸면 됩니다.
