# 공간대여 예약 시스템 — 기능 정의 (초안)

2026-10-30 회의 결정 반영 · 작성 노진산

스터디룸 예약 시스템을 공간대여 예약 시스템으로 넓힙니다. 유형은 스터디룸·스튜디오·카페·영화관·파티룸 5개, 지역은 전국입니다. 예약은 지금 설계대로 1시간 칸 단위를 유지하고, 결제는 '확정' 버튼을 누르면 결제 완료로 처리하는 모의 결제로 시작합니다.

## 무엇이 바뀌나

| 항목 | 스터디룸 버전 | 공간대여 버전 |
| --- | --- | --- |
| 대상 | 스터디룸 6개 (101~302호) | 5개 유형의 공간, 전국 |
| 구조 | 룸 하나 = 상품 하나 | 공간(지점) 아래 룸 여러 개 |
| 조회 | 날짜·시간 / 번호·유형 | 유형별, 지역별(시·도 → 시·군·구), 날짜·시간, 검색어 |
| 상세 | 룸 설명, 시설, 가격 | 이미지, 설명, 홍보 문구, 가격, 예약 가능 날짜 |
| 결제 | 없음 (예약 확정만) | 확정 = 결제 완료 (모의 결제) |
| 그대로 | 1시간 칸, 중복 예약 DB 차단, 마이페이지, 후기·게시판, 활동 로그, 크롤링 신규 등록 | |

## 사용자

| 사용자 | 할 수 있는 것 |
| --- | --- |
| 비회원 | 공간 검색·조회, 상세 보기, 후기·게시판 읽기, 회원가입 |
| 회원 | 위 전부 + 예약·결제·취소, 마이페이지, 후기 쓰기, 게시판 글·댓글 |
| 관리자 | 공지 작성, 공간·룸 숨김, 크롤링 결과 확인 |

공간을 직접 등록하는 호스트 기능은 범위 밖입니다. 공간은 크롤링과 가상 생성으로만 들어옵니다.

## 유형 정의와 크롤링 매핑

회의에서 정한 5개 유형을 스페이스클라우드 공간유형에 이렇게 대응시킵니다. 개수는 표본 200개로 추정한 전국 값입니다(`MVP_시뮬레이션_크롤링_수치.md` 참고).

| 우리 유형 | 스페이스클라우드 공간유형 | 추정 개수 |
| --- | --- | --- |
| 스터디룸 | 스터디룸, 회의실, 세미나실, 강의실 | 약 2,050개 |
| 스튜디오 | 촬영스튜디오, 렌탈스튜디오, 호리존, 실외촬영, 녹음실, 라이브방송 | 약 2,200개 이상 |
| 카페 | 카페 | 약 640개 |
| 파티룸 | 파티룸, 공유주방 | 약 4,670개 이상 |
| 영화관 | 대응하는 유형 없음 | — |

- 한 공간이 여러 유형을 달고 있으면 목록의 첫 유형을 대표 유형으로 씁니다.
- **영화관 유형은 따로 정해야 합니다.** 표본에 '영화관' 유형이 없습니다. 공연장으로 채울지, 'TV/프로젝터 + #영화' 해시태그로 고를지, 가상 생성만 할지 정해야 합니다.

## 예약 규칙

- 1시간 칸 단위, 운영 시간은 공간의 영업시간을 따릅니다. 기본값은 09:00–23:00입니다.
- 최소 이용 시간은 룸마다 다릅니다(크롤링한 최소 예약시간, 없으면 1시간). 최대는 연속 4칸입니다.
- 예약은 오늘부터 14일 안만 받습니다.
- 예약 상태는 다음 순서로만 바뀝니다.

```
결제 대기(pending) ─확정(모의 결제)→ 확정(confirmed) ─이용 종료 시각 경과→ 이용 완료(completed)
        │                                   │
        └─10분 경과 → 만료(expired)          └─취소 → 취소(cancelled)
```

- 칸은 '결제 대기'를 만드는 순간 선점합니다. 확정은 이미 선점한 칸을 확정하는 것이라 이 단계에서는 칸 충돌이 나지 않습니다.
- 만료·취소되면 칸을 반납합니다.
