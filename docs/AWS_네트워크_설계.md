## MariaDB: RDS vs EC2 직접 설치

RDS가 낫습니다. EC2 직접 설치보다 월 약 $13 비싸지만, DB를 인터넷 없는 프라이빗 서브넷에 두기 쉽고 백업·패치를 AWS가 맡습니다. 동시성 테스트 결과도 각자의 DB 설정 차이에 덜 흔들립니다.

| 기준 | RDS for MariaDB (권장) | EC2에 MariaDB 직접 설치 |
| --- | --- | --- |
| 월 비용 (서울, 24시간) | db.t4g.micro $0.025/h ≈ $18.3 + 스토리지 20GB ≈ $2.6 | t4g.micro $0.0104/h ≈ $7.6 + EBS |
| 프라이빗 서브넷 배치 | 그대로 가능 (설치·패치를 AWS가 함) | 패키지 설치에 인터넷이 필요 → NAT, 또는 S3 게이트웨이 엔드포인트 우회 |
| 백업·복구 | 자동 백업, 시점 복구 | 직접 mysqldump·스냅샷 |
| 팀원 간 재현성 | 같은 파라미터 그룹을 쓰면 설정이 같음 | 각자 설치·설정 차이가 생김 |
| 서브넷 요구 | DB 서브넷 그룹에 AZ 2개 필요 | 1개로 충분 |
| 배우는 것 | 관리형 DB 운영 | 리눅스 DB 설치·튜닝 |

EC2 설치가 나은 경우는 크레딧이 빠듯하거나, 수업에서 DB 설치 실습이 필요할 때입니다.

## 개인별 VPC 대역

계정이 따로라 대역이 겹쳐도 당장은 문제없습니다. 하지만 나중에 VPC 피어링이나 공용 모니터링으로 묶을 수 있으니 처음부터 팀원 번호로 나눕니다. 기본 VPC(172.31.0.0/16)와 흔한 10.0.0.0/16은 피합니다.

| 팀원 | VPC CIDR | Nginx 사설 IP | FastAPI #1 / #2 사설 IP |
| --- | --- | --- | --- |
| 1번 | 10.11.0.0/16 | 10.11.1.10 | 10.11.1.11 / 10.11.2.11 |
| 2번 | 10.12.0.0/16 | 10.12.1.10 | 10.12.1.11 / 10.12.2.11 |
| 3번 | 10.13.0.0/16 | 10.13.1.10 | 10.13.1.11 / 10.13.2.11 |
| 4번 | 10.14.0.0/16 | 10.14.1.10 | 10.14.1.11 / 10.14.2.11 |
| 5번 | 10.15.0.0/16 | 10.15.1.10 | 10.15.1.11 / 10.15.2.11 |

FastAPI 사설 IP를 인스턴스 생성 때 고정해 두면 Nginx `upstream` 설정 파일을 팀원끼리 대역 숫자만 바꿔 같이 쓸 수 있습니다.

## 서브넷과 라우팅 (팀원 n번 = 10.1n.x.x)

리전은 서울(ap-northeast-2), AZ는 2a와 2c를 씁니다.

| 서브넷 | CIDR | AZ | 들어가는 것 | 라우팅 |
| --- | --- | --- | --- | --- |
| public-a | 10.1n.1.0/24 | 2a | Nginx (탄력적 IP), FastAPI #1 (+ 크롤러 cron) | 0.0.0.0/0 → 인터넷 게이트웨이 |
| public-c | 10.1n.2.0/24 | 2c | FastAPI #2 | 0.0.0.0/0 → 인터넷 게이트웨이 |
| private-db-a | 10.1n.21.0/24 | 2a | RDS MariaDB (주 인스턴스) | VPC 내부만 (인터넷 경로 없음) |
| private-db-c | 10.1n.22.0/24 | 2c | RDS 서브넷 그룹용 (Multi-AZ 전환 대비) | VPC 내부만 |
| private-app-a/c | 10.1n.11.0/24, 10.1n.12.0/24 | 2a, 2c | 비워 둠 (2단계에서 FastAPI 이전용) | 2단계에 NAT 연결 |

- **게이트웨이:** 인터넷 게이트웨이 1개(무료)만 둡니다. NAT 게이트웨이는 서울 기준 $0.059/h(월 약 $43)에 데이터 처리 $0.059/GB가 추가돼, MVP 전체 비용과 맞먹어서 뺍니다.
- **FastAPI 공인 IP:** FastAPI 2대는 패키지 설치와 크롤링 때문에 인터넷 출구가 필요해 퍼블릭 서브넷에 두고 공인 IP를 받습니다. 대신 보안 그룹으로 Nginx 외에는 들어오지 못하게 막습니다.
- **2단계 이전:** FastAPI를 private-app으로 옮기고 NAT 게이트웨이 1개를 붙입니다(단일 AZ).
- **Grafana·Loki 위치:** VPC 밖(Grafana Cloud 또는 로컬 Docker)에 둡니다. 인스턴스를 늘리지 않으려는 것입니다.
- **그림:** 디자인 캔버스의 '시스템 아키텍처' 페이지에 이 구성을 그렸습니다.

## 보안 그룹

인바운드는 보안 그룹끼리 참조해서, 사설 IP가 바뀌어도 규칙을 고칠 필요가 없게 합니다.

| 보안 그룹 | 붙는 곳 | 인바운드 허용 |
| --- | --- | --- |
| sg-web | Nginx | 80·443 ← 0.0.0.0/0, 22 ← 내 공인 IP/32 |
| sg-app | FastAPI #1·#2 | 8000 ← sg-web, 22 ← 내 공인 IP/32 |
| sg-db | RDS MariaDB | 3306 ← sg-app |

- SSH는 내 IP/32만 엽니다. 집·강의장에서 IP가 바뀌면 규칙도 바꿔야 하므로, 귀찮으면 SSM Session Manager로 22번 포트 없이 접속합니다.
- Locust는 MVP(동시 50명)에서는 내 노트북에서 Nginx 공인 IP로 보냅니다. 2단계(200명)부터는 같은 VPC의 public-a에 Locust EC2를 따로 띄워 Nginx 사설 IP로 보냅니다.

## 공인 IP

공인 IPv4는 붙어 있든 놀든 개당 $0.005/h(월 약 $3.65)입니다.

| 대상 | 종류 | 이유 |
| --- | --- | --- |
| Nginx | 탄력적 IP (고정) | 접속 주소·도메인이 바뀌지 않게 |
| FastAPI #1·#2 | 자동 할당 공인 IP | 출구용. 인스턴스를 멈추면 반납되어 요금이 멈춤 |
| RDS | 없음 (퍼블릭 액세스 끔) | 프라이빗 서브넷에서만 접근 |

탄력적 IP는 인스턴스를 꺼도 요금이 계속 나가니, 오래 안 쓸 때는 반납합니다.

## 팀원별 체크리스트

- [ ] 리전을 서울(ap-northeast-2)로 맞췄다
- [ ] 내 번호의 VPC 대역(10.1n.0.0/16)과 서브넷 5개를 만들었다
- [ ] 인터넷 게이트웨이를 붙이고 퍼블릭 라우팅 테이블에만 연결했다
- [ ] 보안 그룹 3개를 만들고 SSH는 내 IP/32만 열었다
- [ ] RDS MariaDB를 퍼블릭 액세스 끔, DB 서브넷 그룹(2a·2c)으로 만들었다
- [ ] FastAPI 사설 IP를 .1.11, .2.11로 고정하고 Nginx upstream에 넣었다
- [ ] AWS Budgets 월 예산 알림을 걸었다
