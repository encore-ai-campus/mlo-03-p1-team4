# 백엔드 B 진행상황 및 오늘 작업 계획

- 작성일: 2026-11-05
- 기준: `STATE.md`, `docs/백엔드_B_공간_예약_결제_크롤링.md`
- 오늘 계획은 현재 진행 상황을 바탕으로 한 작업 제안이며, 완료로 기록된 항목은 기존 검증 기록을 옮겼습니다.

## 현재까지 개발된 내용

### 완료·검증된 API

- **F-10~11 기준 정보**: 공간 유형, 지역, 시설 조회를 구현했습니다.
- **F-12~13 검색·정렬**: `GET /venues`에 이름·유형·지역·날짜·시간·인원·시설 필터와 페이지네이션을 적용했습니다. 기본·인기·가격·평점 정렬을 지원하며, 필터를 적용한 전체 건수를 응답합니다.
- **F-20 공간 상세**: 상세 정보와 시설·이미지를 반환합니다. 이미지가 없거나 비어 있으면 대표 이미지와 갤러리에 `art:group-0`을 반환하도록 정했습니다.
- **F-21~22 예약 가능 날짜·시간 칸**: 날짜별 빈 칸·연속 예약 가능 여부와 공간별 점유 칸을 반환합니다.
- **예약 소유권 지원 함수**: 후기 작성 검증용 `get_owned()`는 [`backend/app/repositories/reservation_repo.py` 11행](../../backend/app/repositories/reservation_repo.py#L11)에 있습니다. 관련 예약 모델을 DDL에 맞춰 준비했습니다. 이 작업은 예약 생성 API 완료를 의미하지 않습니다.

### 검증 기록과 반영 상태

- `STATE.md`의 11월 5일 기록 기준으로 `test_venues.py` 122건, 백엔드 전체 pytest 161건, 실제 HTTP 브라우저 확인 1건이 통과했습니다. Ruff 및 프론트 검증도 통과한 것으로 기록되어 있습니다.
- F-12·13 변경은 커밋 완료했습니다.
- F-20 이미지 누락 시 기본 이미지는 `art:group-0`입니다. 별도 유형별 대체 이미지는 두지 않습니다.
- **NEW 기준**은 한국 날짜 기준 오늘을 포함한 최근 14일입니다. 날짜 차이가 `0 <= 오늘 - 등록일 < 14`인 공간을 포함하고, 미래 등록일은 제외합니다. F-14 조회 API에 이 기준을 적용합니다.

## 오늘 작업 계획 제안

### 1순위 — F-14 NEW 공간 조회 마무리

- 기존 NEW 판정 로직을 사용해 `GET /venues/new`를 연결합니다.
- 활성 공간만 최신 등록순으로 반환하고, 응답에 `registered_on`과 `new_days_left`를 포함합니다.
- 오늘·13일 전 등록 공간은 포함하고, 14일 전·미래 등록 공간은 제외되는지 확인합니다.

### 2순위 — F-30~32 예약 생성 핵심 구현

- `POST /reservations`에서 예약, 예약 시간 칸, 결제를 하나의 트랜잭션으로 저장합니다.
- `venues`와 예약 소유권 검증은 primary에서 처리합니다. 빈 칸을 먼저 조회해 중복을 막지 않고 `reservation_slots` 기본키가 최종 차단하도록 합니다.
- 중복 키 1062만 롤백 후 겹친 칸을 primary에서 다시 읽어 409 `SLOT_TAKEN`과 `detail.slots`로 응답합니다.
- 동일한 사용자·공간·날짜·시작·시간 요청이 10분 안에 다시 들어오면 기존 예약을 200으로 반환합니다.
- 예약 종료 시각이 이미 지난 경우 생성 시 상태를 `completed`로 저장합니다.

### 3순위 — MariaDB 검증 및 다음 작업 연결

- 성공 시 세 표가 함께 생성되고, 실패 시 모두 롤백되는지 확인합니다.
- 동일 요청 재시도는 같은 예약 ID를 반환하고 새 행을 만들지 않는지 확인합니다.
- 같은 칸 동시 50건 요청에서 성공 1건·409 49건인지 실제 MariaDB `spacecube_test`에서 확인합니다. SQLite는 사용하지 않습니다.
- 예약 생성 검증이 끝나면 F-40 내 예약 조회를 이어서 구현합니다. 취소·완료 배치는 그 다음 단계로 둡니다.

## 통합·협업 확인

- A 파트에서 전달받은 파일은 현재 로컬에 있습니다.
  - 앱 등록·공통: `backend/app/main.py`, `backend/app/core/*` (`db.py`, `deps.py`, `errors.py`, `events.py`, `clock.py`, `security.py`, `metrics.py`, MongoDB·로그 모듈 등)
  - 라우터: `routers/auth.py`, `users.py`, `reviews.py`, `events.py`, `health.py`
  - 모델·저장소: `models/base.py`, `models/user.py`, `models/review.py`, `repositories/user_repo.py`, `repositories/review_repo.py`
  - 스키마: `schemas/auth.py`, `events.py`, `reviews.py`, `users.py`
  - 서비스: `services/auth_service.py`, `event_service.py`, `health_service.py`, `review_service.py`, `user_service.py`
- 이 파일들은 현재 Git 추적 대상에 통합되지 않은 로컬 의존 코드입니다. A 변경을 공유 브랜치에 합친 뒤 import·인증·라우터 등록을 확인하고, MariaDB 기반 백엔드 전체 테스트와 예약 API 통합 테스트를 다시 실행해야 합니다.
- 예약 API는 A 파트의 `get_current_user()`, DB 세션, 오류 처리, 이벤트·지표 함수와 연결됩니다. 약속된 이름과 반환 형태는 유지합니다.
- 오프라인 가상 데이터 생성은 DB 파트 작업으로 병행할 수 있습니다. 생성기가 사용할 공간 데이터가 필요하므로 `/internal/venues` 또는 준비된 공간 데이터 공급 일정을 DB 담당과 맞춥니다.
