# 11-03 FE 확정안 반영 계획·진행

목적: 확정된 `docs/프론트_변경목록_11-03.md` FE-1~9를 기존 Vue 화면에 적용한다. 사용자 지시로 FE만 구현하며 다른 파트 코드는 바꾸지 않는다.

기준: 백엔드 A·B 문서 5절, 오류코드, UI 패턴. 새 패키지 없음. 일반 CSS·기존 토큰·Noto Sans KR·reka 래퍼 유지. API 응답에 옛 room 필드를 추가하지 않는다.

## 작업과 검증

- [x] API·목업: `src/api/**`, 요청 처리·세션·이벤트, auth store. 명세 응답 그대로, 결제 한 번·재전송·충돌·과거 예약·가입·탈퇴·후기 자격 단위 테스트.
- [x] 예약 화면: SearchPage, RoomPage, ReservePage, useBooking. `/reserve?venue=&date=&start=&hours=&people=` 선택값만 이동, 결제에서 POST. 409 다시 선택·내 예약 충돌, 200 성공, 과거 completed.
- [x] 회원·후기: AuthPage, MyPage, BoardPage. 가입 동의·검증·로그인 후 getMe, 내 예약 3상태, 후기 목록·내 후기·탈퇴.
- [x] 공통 화면: router·MainPage·layout·domain·날짜 도우미. 주소 전환, 실제 계약 필드, art 이미지, ±365일 날짜·지난 칸, 접근성.
- [x] 통합: 기존 설계 테스트를 새 시나리오로 교체, npm run verify·npm run test:e2e. 데스크톱·모바일 렌더 확인, FE 문서·상태 갱신.

## 내부 인터페이스

- venuesApi: searchVenues(params), getVenue(id), getSlots(id,date), getAvailableDates(id,offset=0,days=14), getFacilities(). 공개 응답 모양은 기준 문서 그대로. slots는 배열.
- catalogApi: getCategories(), getRegions()는 명세 결과, getNewVenues()는 목록 응답. getTodaySlots()는 FE 조합 함수. getRecentReviews()는 목록 응답. API 미정 통계는 목업 표시만.
- reservationsApi: createReservation({venue_id,date,start_hour,hours,headcount,method},token), getReservation(id,token), getMyReservations(token,params), cancelReservation(id,token).
- reviewsApi: getReviews(params), getVenueReviews(id,params), createReview(id,{rating,content},token), getMyReviews(token,params), updateReview(id,body,token), deleteReview(id,token).
- authApi: checkEmail(email), signup(body), login(body). usersApi: getMe(token), updateMe(body,token), changePassword(body,token), withdraw(token).
- date.js: 기존 export 유지, nowInSeoul() 추가({date,hour}), nextDays(n=14,offset=0), dayOffset(date).
- DateStrip: days·v-model 기존 유지, offset·minOffset·maxOffset props와 shift(delta) 이벤트(±14).
- RoomArt: image prop으로 art 키를 받되 기존 kind/tone 지원 유지.
- 이벤트: useEventLogger().log(type,payload)는 venue_id를 최상위로 분리, 허용된 프론트 9종만 전송.
