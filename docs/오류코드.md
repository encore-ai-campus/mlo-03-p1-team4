# 오류 코드 (전체, 11-03 확정)

API가 돌려주는 모든 오류 코드의 **유일한 기준**입니다. 백엔드는 이 표에 있는 코드만 쓰고, 프론트는 이 표의 '프론트 동작'대로 처리합니다. 새 코드가 필요하면 이 표부터 고치고 A·B·프론트에 알립니다.

## 1. 응답 형식

```json
{"code": "SLOT_TAKEN", "message": "다른 분이 먼저 결제한 시간이 있어요.", "detail": {"slots": [14]}}
```

- `code`: 아래 표의 영문 대문자. 프론트는 `code`로 분기하고 `message`로 분기하지 않습니다.
- `message`: 사용자에게 그대로 보여도 되는 한국어 문장(아래 표의 문구). 내부 정보(SQL, 스택, 다른 사람 정보)를 넣지 않습니다.
- `detail`: 코드별로 정해진 모양만. 없으면 `null`.
- 200·201·202·204가 아닌 응답은 전부 이 형식입니다. FastAPI 기본 오류(422, 404, 405, 500)도 예외 처리기에서 이 형식으로 바꿉니다.

## 2. 공통 (A가 `core/errors.py`에서 처리)

| 코드 | HTTP | 언제 | 사용자 문구 | detail | 프론트 동작 |
| --- | --- | --- | --- | --- | --- |
| `VALIDATION` | 400 | 요청 형식·값이 틀림 (Pydantic 422 포함, 51건 넘는 이벤트 묶음, 모르는 정렬·유형 값) | 입력한 내용을 다시 확인해 주세요. | `{"fields": [{"field": "birth", "reason": "6자리 숫자"}]}` | 해당 입력 칸 아래에 `reason` 표시 |
| `UNAUTHORIZED` | 401 | 토큰 없음·서명 틀림·탈퇴 회원, 내부 키 없음·틀림, `X-Synthetic`인데 `X-Synthetic-Key` 없음·틀림(11-05 A6) | 로그인이 필요해요. | `null` | 로그아웃 → `/login?next=<지금 주소>`, 고르던 값 유지 |
| `TOKEN_EXPIRED` | 401 | 토큰 만료(60분) | 로그인 시간이 끝났어요. 다시 로그인해 주세요. | `null` | `UNAUTHORIZED`와 같음 |
| `FORBIDDEN` | 403 | 남의 후기 수정·삭제 | 이 작업은 할 수 없어요. | `null` | 토스트 |
| `NOT_FOUND` | 404 | 없는 경로, 아래 개별 코드가 없는 리소스 | 찾는 내용이 없어요. | `null` | 없는 페이지 화면 |
| `METHOD_NOT_ALLOWED` | 405 | 경로는 있는데 메서드가 틀림 | 요청을 처리하지 못했어요. | `null` | 토스트 (개발 중 버그 신호) |
| `INTERNAL_ERROR` | 500 | 처리 못 한 예외(1062 외 DB 오류 포함) | 잠시 후 다시 시도해 주세요. | `{"request_id": "…"}` | 토스트 + 다시 시도 버튼. `request_id`로 Loki 검색 |
| `SERVICE_UNAVAILABLE` | 503 | primary DB 연결 안 됨 (`/health`도 503), DB 연결 풀 대기 3초 초과, 서버 동시 요청 상한 초과 | 서비스 점검 중이에요. 잠시 후 다시 시도해 주세요. | `null` | 전체 화면 안내, 30초 뒤 다시 시도 |

- 500을 낼 때 서버 로그(`app.log`)에 `request_id`, 경로, 예외를 남기고, 응답에는 `request_id`만 줍니다.
- replica·MongoDB 장애는 오류가 아닙니다(primary로 대체, 이벤트만 유실). 사용자에게 보이지 않습니다.

## 3. 회원·후기 (A)

| 코드 | HTTP | API | 언제 | 사용자 문구 | detail | 프론트 동작 |
| --- | --- | --- | --- | --- | --- | --- |
| `EMAIL_TAKEN` | 409 | `POST /auth/signup` | 이메일 중복(지금 회원만. 탈퇴하면 이메일을 바꿔 두므로 같은 이메일로 다시 가입 가능, 11-03 A4) | 이미 가입된 이메일이에요. | `null` | 이메일 칸 오류 |
| `INVALID_CREDENTIALS` | 401 | `POST /auth/login` | 이메일·비밀번호 틀림, 탈퇴 회원 (어느 쪽인지 알려주지 않음) | 이메일 또는 비밀번호가 맞지 않아요. | `null` | 폼 위 오류, 비밀번호 칸 비움. **이 401은 로그인 화면으로 보내지 않음** |
| `HAS_UPCOMING_RESERVATION` | 409 | `DELETE /users/me` | 취소할 수 있는 예약(`confirmed`이고 아직 시작 전)이 남음. 이용 중인 예약은 막지 않음(11-05) | 이용 예정 예약이 있어요. 예약 내역에서 먼저 취소해 주세요. | `{"count": 2}` | 탈퇴 창에 문구 + 예약 내역 링크, 탈퇴 버튼 끔 |
| `WRONG_PASSWORD` | 400 | `PATCH /users/me/password` | 현재 비밀번호 틀림 | 현재 비밀번호가 맞지 않아요. | `null` | 현재 비밀번호 칸 오류 |
| `RESERVATION_NOT_FOUND` | 404 | `POST /reservations/{id}/review` | 없거나 남의 예약 | 예약을 찾을 수 없어요. | `null` | 토스트, 내 예약 다시 불러오기 |
| `NOT_COMPLETED` | 403 | 같음 | 이용 완료 전 | 이용이 끝난 뒤에 후기를 쓸 수 있어요. | `null` | 후기 버튼 숨김 |
| `REVIEW_PERIOD_OVER` | 403 | 같음 | `max(이용일, 예약한 날)` + 7일 지남 | 후기를 쓸 수 있는 기간이 지났어요. | `{"deadline": "2026-11-10"}` | 후기 버튼 숨김 |
| `REVIEW_EXISTS` | 409 | 같음 | 이 예약에 이미 후기 있음 | 이미 후기를 썼어요. | `{"review_id": 3}` | 내 후기로 이동 |
| `REVIEW_NOT_FOUND` | 404 | `PATCH·DELETE /reviews/{id}` | 없거나 삭제된 후기 | 후기를 찾을 수 없어요. | `null` | 목록 다시 불러오기 |

- 가입 칸 검증(비밀번호 8자 이상·72바이트 이하, birth 6자리 실제 날짜, gender_digit 1~4, 이메일 형식·100자, 필수 동의 2개 `true`, 만 14세 이상)은 모두 `VALIDATION`이고 `detail.fields`로 칸을 알려 줍니다. 14세 미만은 `{"field": "birth", "reason": "under_14"}`.
- `POST /events`는 모르는 `event_type`이 있어도 오류가 아닙니다(202 + `ignored`).

## 4. 공간·예약·결제·크롤링 등록 (B)

| 코드 | HTTP | API | 언제 | 사용자 문구 | detail | 프론트 동작 |
| --- | --- | --- | --- | --- | --- | --- |
| `VENUE_NOT_FOUND` | 404 | `GET /venues/{id}…`, `POST /reservations` | 없는 공간, `is_active = false` | 공간을 찾을 수 없어요. | `null` | 없는 페이지 화면 |
| `OUT_OF_RANGE` | 400 | `POST /reservations`, `GET /venues`·`slots`·`available-dates` | 날짜가 ±365일 밖, 영업시간 밖, `min_hours` 미만·4칸 초과 | 예약할 수 없는 날짜나 시간이에요. | `{"reason": "date" \| "hours" \| "min_hours" \| "max_hours", "min_date", "max_date", "min_hours"}` | 해당 선택 해제, `reason`별 안내 |
| `TOO_MANY_PEOPLE` | 400 | `POST /reservations` | 인원 > `capacity_max` | 이 공간은 최대 {n}명까지예요. | `{"capacity_max": 6}` | 인원 칸 오류 |
| `INVALID_METHOD` | 400 | `POST /reservations` | 결제수단이 `transfer`·`card`·`phone`이 아님 | 결제 수단을 다시 골라 주세요. | `null` | 결제수단 칸 오류 |
| `SLOT_TAKEN` | 409 | `POST /reservations` | 먼저 결제한 사람이 있음(1062). 겹친 칸이 내 다른 예약이면 `mine` | 다른 분이 먼저 결제한 시간이 있어요. (`mine`이면: 이미 내 예약과 겹치는 시간이에요.) | `{"slots": [14, 15]}`, 내 예약과 겹치면 `+ "mine": true, "reservation_id"` | 그 칸을 마감 표시, 선택 해제, 칸 다시 고르기. `mine`이면 내 예약으로 이동 버튼 |
| `RESERVATION_NOT_FOUND` | 404 | `GET /reservations/{id}`, `POST …/cancel` | 없거나 남의 예약 | 예약을 찾을 수 없어요. | `null` | 내 예약 다시 불러오기 |
| `ALREADY_CANCELLED` | 409 | `POST …/cancel` | 이미 취소됨 | 이미 취소된 예약이에요. | `null` | 내 예약 다시 불러오기 |
| `NOT_CANCELLABLE` | 409 | `POST …/cancel` | 이용 시작 뒤, `completed`(지난 시간 예약 포함) | 이용이 시작된 예약은 취소할 수 없어요. | `null` | 취소 버튼 숨김 |
| `UNKNOWN_REGION` | 400 | `POST /internal/venues` | 모르는 시·도/시·군·구 | (크롤러용) 등록되지 않은 지역 | `{"sido", "sigungu"}` | 크롤러가 `crawl_raw.exclude_reason`에 기록 |
| `UNKNOWN_CATEGORY` | 400 | `POST /internal/venues` | 모르는 유형 코드 | (크롤러용) 등록되지 않은 유형 | `{"category_code"}` | 같음 |

- 검색의 모르는 `sort`·`category` 값, `page`·`size` 범위 밖은 `VALIDATION`입니다.
- `/internal/venues`의 값 검증(가격 > 0, 인원 ≥ 1, 영업시간, `min_hours` 1~4)은 `VALIDATION`입니다.
- 1062가 아닌 DB 오류(외래키 1452 등)는 409로 바꾸지 않고 `INTERNAL_ERROR`로 둡니다(앞 단계 검증이 빠졌다는 신호).
- 같은 사용자가 같은 공간·날짜·시작·시간으로 10분 안에 다시 결제하면 오류가 아니라 **200 + 처음 예약**입니다(두 번 누름·재시도, 11-03 A4).

| 코드 | 언제 | 사용자 문구 | 동작 |
| --- | --- | --- | --- |
| `NETWORK_ERROR` | `fetch` 자체가 실패(서버 꺼짐, 오프라인) | 인터넷 연결을 확인해 주세요. | 토스트 + 다시 시도 |

## 6. 지키는 것

- 401은 `INVALID_CREDENTIALS`(로그인 폼)만 빼고 모두 로그인 화면으로 보냅니다. 이 분기는 `client.js` 한 곳에서 합니다.
- 같은 상황에 코드 두 개를 쓰지 않습니다. 남의 예약은 '있다'는 것도 알리지 않게 403이 아니라 404 `RESERVATION_NOT_FOUND`입니다.
- 테스트는 HTTP 상태와 `code`를 함께 확인합니다(`assert r.status_code == 409 and r.json()["code"] == "SLOT_TAKEN"`).
- 오류 응답도 Prometheus `http_requests_total{status}`에 잡힙니다. 409 `SLOT_TAKEN`은 정상 경쟁이라 오류율 경보에서 뺍니다.
