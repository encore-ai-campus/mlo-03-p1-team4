# 데이터 수집 명세 — 수집 속성과 생성 데이터 섞기

2026-11-05 작성 노진산(PM) · 2026-11-06 사진 후보 현행화 · 상태: **1차 수집원 2곳 + 부족분 생성 방향 확정(사용자 결정)**. 2026-11-06 사용자 요청으로 CCL 사진을 5개 유형별 8장씩 총 40장으로 확장하고 프론트 분위기 참고 이미지로 연결했습니다. 사이트별 약관·robots.txt 확인 기록은 11-05 기준이며 실행 전에 다시 확인. 기준: `crawler/AGENTS.md`, `산출물_04_DB명세서.md`

시연용 공간 30개를 목표로, 두 사이트에서 확인한 **속성**을 일부 참고하고 부족한 공간과 과거 사용자 행동 데이터는 규칙 기반 생성기로 채웁니다. 외부 속성을 참고한 공간도 업체의 실제 예약 상품이 아닙니다.

- **1차 수집원 2곳:** 스페이스클라우드 · 쉐어잇. **속성(유형·인원·시간당 가격·최소 시간·시설·영업시간·지역)만** 참고합니다. 루북·스파크플러스는 1차 수집 대상에서 제외합니다.
- **부족분:** 30개 목표에서 최종 검토를 통과한 속성 기반 공간을 제외한 나머지를 생성합니다. 첫 목표는 속성 기반 15~20개이며 확보 가능한 수로 조정합니다.
- **이미지 현행 기준:** 프론트가 `public/photos/`의 CCL 분위기 참고 사진을 유형·공간 ID로 안정 선택해 표시하고, 사진 누락 때는 유형별 일러스트를 씁니다. 실제 등록 공간을 촬영한 사진으로 표시하지 않으며 이미지 API `art:<종류>-<색>` 계약은 그대로입니다. 크롤링한 공간 사진은 저장·게시하지 않습니다.
- 공공데이터 OpenAPI(서울시 공공서비스예약)는 11-05 PM 결정으로 쓰지 않습니다.

> 법률 자문이 아닙니다. 약관·판례를 읽고 수업 프로젝트 기준으로 위험을 줄이는 쪽으로 정한 것입니다. 약관은 바뀔 수 있으니 발표 전에 다시 확인합니다.

## 4. 사진 — CCL 분위기 참고 이미지

2026-11-06 사용자 요청에 따라 Wikimedia Commons의 파일별 라이선스를 확인해 5개 유형마다 8장씩 총 40장을 준비했습니다. 유형은 스터디룸·스튜디오·카페·강의실·파티룸입니다. 1200×780px WebP로 맞췄고, 얼굴·상호·로고·읽을 수 있는 글자·특정 장소 단서가 있는 일부 사진은 생성형 편집으로 정리했습니다. 사진 파일은 `frontend/public/photos/`, 저작자·원본·라이선스·변경 기록은 [SOURCES.md](../frontend/public/photos/SOURCES.md)에 있습니다.

이 사진은 **유형의 분위기를 설명하는 예시**이지, 다락큐브에 등록된 실제 공간을 촬영한 것이 아닙니다. 프론트는 유형과 venue ID를 해시해 같은 공간에는 같은 사진을 안정적으로 고르고, 상세 갤러리는 컷 번호를 선택 키에 더합니다. 화면에는 '분위기 참고'라고 표시하며 푸터에서 [사진 출처·라이선스](../frontend/public/photos/credits.html)를 열 수 있습니다. 이 연결은 프론트에서만 처리하고 `art:<종류>-<색>` API 계약과 DB에 손대지 않습니다.

- **고르는 기준:** 얼굴·업체명·간판·로고·읽을 수 있는 식별 표식이 없는 사진을 고릅니다. 남아 있는 식별 단서는 생성형 편집으로 정리하고, 원본·저작자·라이선스·변경 사실을 파일마다 기록합니다. 각 사진은 실제 등록 공간이 아닌 유형 분위기 예시로만 씁니다.
- **저장:** `frontend/public/photos/<유형>/`에 1200×780px WebP(400:260), 품질 82로 보관합니다. 장당 약 34~167KB, 40장 합계 약 3.29MB입니다. 출처·라이선스·변경 내역은 [SOURCES.md](../frontend/public/photos/SOURCES.md), 이용자에게 보이는 크레딧은 [credits.html](../frontend/public/photos/credits.html)에 있습니다.
- **API로 가져오지 않습니다.** Unsplash·Pexels API는 출처 표시 방식과 원본 주소 사용(핫링크) 같은 별도 규칙이 있고 키가 필요해, 사람이 골라 내려받는 편이 단순합니다.
- **화면:** 유형마다 준비된 8장 가운데 venue ID 해시로 사진을 골라 화면 간에 일관되게 사용합니다. 사용자는 사진 위 '분위기 참고' 표시와 푸터의 출처·라이선스 페이지에서 사진 정보를 확인할 수 있습니다.

### 4-2. 네이버·구글 이미지 검색 결과를 가져오면 안 되나

**그대로는 안 됩니다.**

- 검색엔진은 남의 사진을 찾아 보여 주는 통로일 뿐이고, 검색 결과에 나온다고 이용 허락을 받은 것이 아닙니다. 공간 사진 대부분은 업체·블로거가 찍은 저작물이라, 우리 화면에 쓰면 복제·전송이 됩니다.
- 예외는 **CCL 필터**입니다. 네이버 이미지 검색의 'CCL' 옵션, 구글 이미지의 '사용 권한 → 크리에이티브 커먼즈 라이선스' 필터로 거른 사진은 조건만 지키면 쓸 수 있습니다.
  - 다만 **원본 페이지에서 라이선스를 직접 확인**해야 하고(게시자가 진짜 저작권자인지는 검색엔진이 보증하지 않음), BY(출처 표시)·ND(변경 금지)·NC(비영리) 조건을 지켜야 합니다.
  - 그래서 하나하나 확인할 일이 많습니다. 처음부터 조건이 단순한 Unsplash·Pexels·Pixabay를 먼저 쓰고, 부족한 유형만 CCL 필터로 보충합니다.

### 4-3. 그래도 모자라면

- **직접 찍은 사진:** 팀원이 캠퍼스 강의실·스터디 공간을 찍으면 우리 저작물이라 제약이 없습니다(사람 얼굴·게시물 주의).
- **생성 이미지:** 유형별 분위기 이미지를 생성 도구로 만들 수 있습니다. 쓰는 도구의 이용 약관을 확인하고, 실제 사진처럼 오해하지 않게 '예시 이미지'로 표시합니다.

### 5-2. 섞는 수량 목표

| 묶음 | 공간 수 | 속성 | 사진 |
| --- | --- | --- | --- |
| 크롤링 속성 기반 시연용 공간 | 목표 15~20곳 (두 곳에서 선별, 검증 후 수량 조정) | 참고한 속성(인원·가격·시설·지역), 이름·소개는 생성 | 일러스트 풀 |
| 생성기 시연용 공간 | 30곳 목표에서 검증된 속성 기반 공간을 뺀 나머지(처음 예상 10~15곳) | 검증된 속성 분포를 참고한 가상 값 | 일러스트 풀 |

- 공간 이름·소개·후기·예약·결제는 모두 가상이며, 실제 업체의 예약 가능 여부와 무관합니다. `venues`에는 `is_synthetic` 컬럼이 없으므로 `source_site`는 **속성 출처**로만 읽고, 화면과 발표에서는 전체 공간을 시연용으로 표시합니다. 생성 회원·예약·이벤트는 `is_synthetic = true`로 구분합니다.
- 과거 사용자 행동 데이터는 1차로 **30일분** 생성합니다. DB 명세의 하루 약 420세션·2,500이벤트·125예약을 적용하면 약 1만 2,600세션·7만 5천 이벤트·3,750예약입니다. 이는 가정한 시나리오의 출력이며 관측 수요나 실제 예약 전환율이 아닙니다. 90일분은 주간 추세 확인이 필요할 때만 확장합니다.
- 생성기가 MongoDB에 직접 쓴 이벤트만으로는 API의 `events.log`→Loki·MongoDB 이중 기록을 검증할 수 없습니다. 그 경로는 API 연결 후 별도 부하 시험으로 확인합니다.
