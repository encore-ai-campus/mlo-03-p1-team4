# PRO_1 크롤링 대상 사이트 조사

2026-11-02 · 노진산

> **11-03 결정 (A3):** 유형을 **스터디룸·스튜디오·카페·강의실·파티룸**로 바꿨습니다(영화관은 시간 단위 대여처가 없어 뺌). 크롤링은 **3곳**: ① 스페이스클라우드(주) ② 쉐어잇(강의실·파티룸·촬영이 많음) ③ 루북(세미나실·강의실 위주, `*`는 `/api`·`/graphql`·관리 경로만 차단). 2026-11-03에 robots.txt를 다시 받아 확인했습니다. ②③은 이용약관 확인과 상세 20건 표본 승인 뒤에 수집합니다. 루북은 화면이 스크립트로 그려져 HTML에 값이 있는지 표본 1건으로 먼저 확인합니다. 아워플레이스는 여전히 `*` 전체 차단이라 제외. 공공 OpenAPI(공유누리)는 강의실 보강용 후보로 남깁니다.

5개 유형(스터디룸·스튜디오·카페·파티룸·영화관)에 쓸 데이터를 어디서 가져올지 정하려고 후보 사이트를 다시 조사했습니다. 결론은 **크롤링은 스페이스클라우드(주)와 쉐어잇(보조) 두 곳, 나머지는 공공 OpenAPI로 채우기**입니다. 영화관은 시간 단위로 빌려주는 플랫폼이 없어서, 크롤링 대신 공공 인허가 데이터와 가상 생성으로 채웁니다. 사이트 추가는 `crawler/AGENTS.md`에 따라 회의에서 승인받은 뒤 진행합니다.

## 후보별 확인 내용

### 스페이스클라우드 (주 대상, 유지)

- robots.txt가 2026-09-01에 바뀌었습니다. AI 검색·학습 봇 항목이 따로 생겼지만, 일반 봇(`*`) 규칙은 10-30과 같습니다. `/search*`, `/reserve/`, `/my/`, `/space/zzim`, `/auth/login`만 막고 `/space/<id>`는 허용합니다.
- `Python-urllib`, `Wget` 같은 도구 이름은 전체 차단 목록에 있습니다. 우리 크롤러(httpx)는 User-Agent를 직접 정해서 보내므로 영향이 없지만, 이 목록에 있는 도구로는 요청하지 않습니다.
- 사이트맵은 그대로 제공됩니다(10-30 기준 공간 14,137개). 크롤러는 지금 구조를 그대로 씁니다.

### 쉐어잇 (보조, 2단계)

- 사이트맵 색인 안에 공간 사이트맵이 21개 있고, 하나에 약 200~214개씩 들어 있어 **공간 약 4,300개**로 추정합니다. 상세 주소는 `/venue/<id>`이고, 마지막 id는 20285입니다.
- 상세 페이지 HTML 안의 `__NEXT_DATA__` JSON에 필요한 값이 구조화되어 있습니다. 스페이스클라우드보다 파싱이 쉽습니다.

  | 값 | JSON 위치 |
  | --- | --- |
  | 시·군·구 | `spaceMetaData.resource.legalAddress.name` (예: '경기도 고양시 덕양구') |
  | 공간 유형 | `spaceMetaData.resource.zone3Types[].type` |
  | 시간 단위·가격 | `goods[].saleInfo.timeUnitMinute`, `price` |
  | 최소·최대 이용 시간 | `goods[].saleInfo.minimumSalesTimeRangeMinute`, `maximumSalesTimeRangeMinute` |
  | 최대 인원 | `goods[].personnelConfig.maximumNumberPersonnel` |
  | 평점·후기 수 | `reviewSummary.ratingAverage`, `totalCount` |

- 같은 JSON에 업체 이름, 호스트 이름, 상세 주소, 위경도도 있습니다. 이 값들은 우리 규칙(시·구까지만, 이름 미사용)에 따라 저장하지 않습니다.
- **걸리는 점 ①:** 열어 본 3건 중 2건이 체육관(대학 시설 포함)이고 1건은 닫힌 공간이었습니다. 우리 5개 유형이 얼마나 들어 있는지는 표본 측정이 필요합니다(상세 20건, 사람 승인 범위 안).
- **걸리는 점 ②:** 이용약관 원문을 찾지 못했습니다. 사이트 아래쪽에 '이용약관' 글자만 있고 링크 주소를 확인하지 못했습니다. 회의 전에 브라우저로 약관 페이지를 열어 크롤링·무단 수집 금지 조항이 있는지 확인해야 합니다.

| [영화상영관 조회서비스](https://www.data.go.kr/data/15154848/openapi.do) | 행정안전부 (지자체 인허가 모음) | 인허가일자, 영업상태, 사업장명, 소재지 주소 | 제한 없음, 무료 | 일간 |

- 약관·robots.txt 걱정이 없고, 수집이 '사이트 긁기'가 아니라 API 호출이라 배치 파이프라인(수집 → 변환 → 적재)을 보여 주기에도 깔끔합니다.
- 공공데이터포털 API는 활용 신청을 해서 인증키를 받아야 합니다. 키는 `.env`에만 두고 `.env.example`에는 이름만 적습니다.
- 응답의 실제 필드 이름은 신청 후 명세에서 확인해야 합니다. 공유누리는 참고 문서가 '복구 중'으로 표시되어 있습니다.
- 공공 회의실·강당은 무료이거나 요금 체계가 달라서, 가격은 스페이스클라우드 분포를 쓰고 공공 데이터는 위치·인원·운영 시간 근거로만 씁니다.

### 영화관

- 시간 단위로 영화관을 빌려 주는 국내 플랫폼은 찾지 못했습니다. 영화관 대관은 대부분 회차·공간 단위 고정 가격입니다.
  - 메가박스 코엑스 '더 부티크 프라이빗': 8석, 대관 40만 원 ([인사이트](https://www.insight.co.kr/news/263404))
  - 서울 소규모 프라이빗 시네마: 을지영화관(한 팀 전용), 웜플레이(2~4명), 무비랜드(30석) 등 ([뉴스와](https://www.news-wa.com/amp/travel/tour-korea/2025/10/17/20251017500026))
- 그래서 **영화상영관 조회서비스로 지역(시·군·구)만 가져오고, 인원·가격·시설은 가상 규칙으로 만드는 방식**을 제안합니다. 예: 인원 2~10명, 시간당 3~6만 원, 시설은 빔프로젝터·음향 고정. 근거는 위 기사 수준의 가격대입니다.
- 영업 중인 상영관만 쓰고(영업상태 필터), 사업장명은 저장하지 않습니다(11-01 검토의 '이름 미사용' 규칙과 같음).

## 제안

1. **MVP:** 지금처럼 스페이스클라우드 한 곳만 씁니다. 영화관은 가상 생성만 합니다.
2. **2단계:** 쉐어잇을 더합니다. 그 전에 ① 약관 확인, ② 상세 20건 표본으로 5개 유형 비율 측정, ③ 회의 승인 순서로 진행합니다.
3. **같이 검토:** 공공 OpenAPI 세 가지는 약관 걱정이 없어서 MVP에 넣어도 됩니다. 넣는다면 영화상영관 조회서비스부터 넣는 게 좋습니다. 비어 있는 영화관 유형을 바로 채울 수 있습니다.

## 회의에서 정할 것

- [ ] 크롤링 사이트: 스페이스클라우드 단독(MVP) → 쉐어잇 추가(2단계)
- [ ] 쉐어잇 약관 확인 담당과 표본 20건 측정 승인
- [ ] 공공 OpenAPI(영화상영관 / 공유누리 / 서울시)를 MVP에 넣을지, 넣으면 어느 것부터
- [ ] 영화관 유형: 상영관 인허가 데이터로 지역만 가져오고 나머지는 가상 생성
- [ ] 공공데이터포털 인증키 신청 담당 (키는 `.env`에만)

정해지면 고칠 곳: `crawler/AGENTS.md`(대상 사이트 목록), `crawler/README.md`, `MVP_시뮬레이션_크롤링_수치.md`(크롤링 대상 행), `공간대여_01_기능정의.md`(영화관 매핑).
