## 2. 바뀌는 흐름 — 예약·결제

```
지금:  칸 선택 → [예약 신청] POST /reservations (pending) → /reservations/:id 결제 화면(10분) → [결제] /confirm
바뀜:  칸 선택 → 결제 화면(서버 호출 없음, 선택값만 들고 감) → [결제] POST /reservations (method 포함) → 완료
```

- 결제 화면 라우트는 예약 id 대신 선택값으로 엽니다. 예: `/reserve?venue=7&date=2026-11-05&start=13&hours=2&people=4`. 이름·경로는 프론트가 정하고 `산출물_03` 화면 지도에 적습니다.
- 요청 본문: `{venue_id, date, start_hour, hours, headcount, method}`. `method`는 `transfer`·`card`·`phone` (휴대폰 결제 추가).
- 결제 응답이 **200이어도 성공**입니다(같은 요청을 다시 보낸 경우, 처음 예약이 옴). 409에 `detail.mine`이 있으면 '이미 내 예약과 겹치는 시간'으로 안내하고 내 예약으로 보냅니다.
- 409 `SLOT_TAKEN`이면 `detail.slots`의 칸을 바로 마감으로 표시하고 결제 화면에서 칸을 다시 고르게 합니다(토스트 문구: "다른 분이 먼저 결제한 시간이 있어요.").
- 성공 응답 201에 `status: "confirmed"`와 `payment`가 옵니다. 완료 화면 → 내 예약.
- 내 예약 탭: `confirmed`(이용 예정) · `completed`(이용 완료) · `cancelled`(취소). `can_cancel`, `review_id`로 버튼을 정합니다.

## 7. Codex 작업 단위 (한 번에 하나씩)

Codex로 진행할 때 아래 FE-1부터 **한 작업씩** 시킵니다. 각 작업은 앞 작업이 끝나 `npm run verify`가 통과한 뒤에 시작합니다. 백엔드는 아직 없으니 **목업(`src/api/mock/`)이 아래 '목업이 흉내 낼 것'을 그대로 따라야** 나중에 `VITE_USE_MOCK=false`로 바꿨을 때 깨지지 않습니다.

### 시작 전에

- `Pro_1` 폴더에서 Codex를 엽니다(루트 `AGENTS.md` → `frontend/AGENTS.md` 순서로 읽음). Codex는 git 저장소 루트를 기준으로 `AGENTS.md`를 찾으므로, 원격 저장소(A5)가 정해지기 전이라도 `Pro_1`에서 `git init` 후 첫 커밋을 해 두면 지침도 잘 읽고 바뀐 내용(diff)도 보기 쉽습니다.
- `frontend/`에서 `npm install`, E2E를 돌릴 PC는 `npx playwright install chromium`.
- 작업마다 Codex에 이렇게 시킵니다:

```text
docs/프론트_변경목록_11-03.md 7절의 FE-<번호>만 해 줘. 기준 문서는 그 작업의 '기준' 칸.

작업 범위 밖 파일은 고치지 말고, 문서와 다른 점이 있으면 고치기 전에 알려 줘.
```
