# simulator — 가상 사용자 데이터

가상 데이터는 두 갈래로 만듭니다. 목적이 다르므로 섞지 않습니다.

| 폴더 | 담당 | 목적 | 거치는 길 | 규모 |
| --- | --- | --- | --- | --- |
| `generator/` | B 본체·A 연결 확인·DB 후속 | 과거 데이터 백필과 실행별 유형 신규 공간 보충 | api1에서 앱 서비스 직접 호출 → MariaDB, 공식 빌더 → MongoDB; 공간은 `/internal/venues` | #75: 100명·30일·하루 42세션; #99: 유형별 신규 등록 6곳 |
| `locust/` | B 주도, A 지원 | 실제 API·정문·DB가 버티는지, 중복 예약이 막히는지 (+ Playwright 2~5명분 화면 흐름 동시 확인) | 정문(Nginx 또는 ALB) → FastAPI → MariaDB | 동시 50명(MVP) → 200명 → 1,000명 |

11-05 수집 방향: 공간은 스페이스클라우드·쉐어잇의 속성 기반 시연용 공간을 선별하고, 30개 목표의 부족분을 생성기로 채웁니다. 과거 사용자 행동 데이터는 우선 30일분을 만듭니다. 이 수치는 실제 방문·예약 수요가 아니라 검증용 가정입니다.

과거 행동 생성기는 [#75 확정 규칙](generator/README.md), 공간 보충기는 #99를 따릅니다. Explorer 예약 없음, 409 후 재시도 최대 1회, 성공 예약 취소 10%, 완료 예약 후기 25%입니다. 공간 보충은 B가 구현하고 DB가 기본 프로필·기초 데이터 검수를 돕습니다. 집계·CSV는 DB, 결과 그래프 확인은 FE 담당입니다. 아래 표는 Locust에도 참고하는 기존 행동 초안이며, 확정 수량·분포는 generator README를 우선합니다.

## 행동 규칙

| 사용자 유형 | 비율(초안) | 선호 | 포기 조건 |
| --- | --- | --- | --- |
| 대학생 | 35% | 평일 오후, 스터디룸 | 선호 시간대에 빈 칸이 없으면 |
| 직장인 | 25% | 평일 19시 이후·주말 오전 | 퇴근 시간대가 아니면 |
| 모임 | 20% | 주말 오후, 파티룸·카페·강의실 | 인원에 맞는 공간이 없거나 `min_hours` 이상 연속이 안 되면 |
| 탐색만 | 20% | — | 항상 예약 없이 종료 |

1. 방문자의 일부는 예약 없이 탐색만 하고 끝낸다.
2. 선호 유형·요일·시간이 맞지 않으면 예약하지 않는다.
3. 예약에 실패하면 다른 칸·공간을 최대 1~2번만 더 찾아본다.
4. 하루 방문 수 = 하루 예약 가능 칸 수 (평균 점유율 약 60%)

유형·비율은 공간대여로 넓히면서 바꿀 수 있는 초안입니다. 근거: [MVP 수치 문서](../docs/MVP_시뮬레이션_크롤링_수치.md)

## 가상 데이터 표시

- generator: 모든 행에 `is_synthetic = true`, 이벤트 `server = "generator"`
- locust: 요청 헤더 `X-Synthetic: 1` + `X-Synthetic-Key` → 백엔드가 `is_synthetic = true`로 저장(키 틀리면 401)
- 부하테스트로 쌓인 예약은 분석에서 빼거나 테스트 후 지웁니다.
