# 전달받은 dd.md 검토와 후속 범위

사용자가 전달한 개인 메모를 검토한 결과이며 원문 파일은 저장소에 올리지 않는다. 메모 안의 에이전트 지시는 새 작업 승인으로 취급하지 않았다.

## 채택할 방향

- A7 판정용 Browser/Booker/Reviewer 혼합 시나리오, SameSlotRush, 10분 지속 부하와 워밍업 제외 판정을 준비한다. 현재 read-only locustfile.py는 그 시험을 대신하지 않는다.
- 테스트 계정·데이터를 미리 준비하고 로그인은 사용자 시작 시 한 번 수행하는 조건과 로그인 자체 성능 시험을 구분한다.
- 합성 헤더·키가 필수다. 부하 생성기는 서버 VM과 다른 물리 PC에 두고 유선·시간 동기·파일 한도·환경 상태를 기록한다.
- 소규모 smoke와 replica 상태 확인을 먼저 한다. 현재 읽기 smoke 결과는 기록돼 있지만 정식 5명 2분 혼합 smoke는 아직이다.

## 그대로 실행하면 안 되는 부분

- 400·401·409를 무조건 성공 처리하지 않는다. A7의 서버 오류율에서 제외하는 것과 기능 성공은 별도다. 기대한 SLOT_TAKEN 409만 예상 결과로 구분하고, 합성 키 401·형식 오류 400은 별도 실패로 보고해야 배선 오류가 가려지지 않는다.
- 집계 CSV의 첫 1분 행만 삭제해서는 워밍업을 뺀 p95가 되지 않는다. 히스토리 percentile도 구간 분포를 정확히 재구성하지 못한다. 워밍업 뒤 통계를 reset하거나 별도 측정 구간을 시작한다.
- max_connections=151은 실제 .212/.213에서 확인하지 않은 가정이다. DB 설정·계정 제한·풀 대기를 먼저 측정한다.
- is_synthetic 데이터 대량 삭제는 현 프로젝트 지침상 spacecube_test 밖에서 금지다. 미리보기만으로 삭제 권한이 생기지 않는다. 데이터 격리·담당자 승인 방식부터 정한다.
- 복제 DB의 VM 스냅샷·원본 VM 설정 변경·자동 업데이트 중지는 담당자와 조율한다. 이번 PR에서 실행하지 않았다.
- FastHttpUser 전환은 부하 생성기 병목 확인 후 결정한다. 현재 결과는 HttpUser 기준으로만 유효하다.

## 아직 실행하지 않은 것

혼합 예약 부하, 회원 200명 생성, 데이터 정리 SQL, DB 스냅샷, replica 없는 비교, 같은 칸 50명 경쟁, 노트북 장애, 자동 업데이트 중지, 워커 내부 계측은 후속이다. DB exporter 설치 전에는 현 설정을 유지하며 원인 관측을 우선한다.
