# Locust 단계 실행기

7대 VM 사전 점검 뒤 읽기·쓰기·경합·혼합 부하를 분리 실행한다. 기존 배포 파일과 서비스 설정은 변경하지 않는다. 상세 계약은 docs/Locust_읽기_쓰기_상세시나리오.md, 이번 구현 순서는 PLAN.md를 따른다.

2026-11-08 이벤트 기록 신뢰성 후속 검증은 [팀 공유 결과](../../../docs/부하실험_이벤트기록_팀공유_2026-11-08.md)와 [실행 계획](../../../docs/superpowers/plans/2026-11-08-event-file-write-load-test.md)을 따른다. 현재 `write_high.py`는 100/200/400 VU, 400개 슬롯까지 지원하며 500/600/800 시험에 쓰기 전용 확장이 필요하다.

비밀값은 실행 환경과 프로세스 메모리에만 둔다. logs/ 아래에 요청 원본(정규화 경로·상태·시간만), fixture ID, 자원 시계열과 결과를 저장한다. 원격 공용 작업판과 서버 작업 잠금을 먼저 확인한다.

## 읽기 증량 전용 실행

`pro_1` Python으로 `read_high.py`를 실행하면 Grafana 원본 저장·35초 후 검증 → 공개 읽기 100/200/400명을 수행한다. 각 60초 워밍업·180초 측정·120초 회복, 오류 시 다음 단계 중단이다. 새 계정·예약·후기·이벤트를 생성하지 않는다. 쓰기 시험은 사용자와 읽기 결과 검토 후 별도로 승인받아 진행한다. 이전 5/20/50과 같은 새 시나리오(10종, 1~5초 생각 시간)를 사용하며 11-06의 4종/1~3초 시나리오와 최대 용량을 직접 비교하지 않는다. `collect_evidence.py <report>`는 DB/자원 구간 지표를 추가 보존한다.


## 재배포 후 쓰기 증량

write_high.py는 현재 정문 API에서 공간·빈 칸을 읽고 합성 계정을 단계별 100/200/400개 준비한다. VU마다 전용 계정·겹치지 않는 미래 시간 칸을 할당하며 예약 201→내역 확인→취소/환불 200→내역 확인을 반복한다. 시간 칸은 취소 후 같은 사용자만 재사용한다. 새 가입/로그인·수동 1건 smoke는 준비 구간으로 분리한다. 각 단계는 읽기와 같은 60초 워밍업·180초 측정·120초 회복, spawn 5명/초·생각 시간 1~5초다. 워밍업/종료 정리까지 포함해 오류 하나라도 있으면 다음 단계에 진입하지 않는다. DB 대량 삭제 없이 자기 합성 계정의 잔여 confirmed 예약만 API로 정리한다. 인증값은 메모리에만 두며 종료하면 재사용하지 않는다.

19:11 시작 run은 배포 인계 local/server-e2e-1107(f0b14c3 기반+로컬 변경), 공간31, Nginx upstream keepalive16/4s 기준이다. 이전 읽기와 코드·설정·데이터가 같지 않으므로 인과적 A/B 비교로 부르지 않는다. deployment-snapshot.json에 실제 conf.d·앱 파일 지문을 보존한다. API1의 완료/집계/크롤러 타이머는 끄지 않고 시험 중 실행 이력을 함께 수집한다.
