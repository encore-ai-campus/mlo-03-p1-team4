# 재배포 후 쓰기 100/200/400 실행 계획

사용자 승인: 현재 설정 유지, VM별 자원/로그 기록 및 읽기 비교, 오류 시 다음 단계 중단. 서버 작업판 CODEX-LOAD-20261107 및 operation lock으로 배포/다른 부하와 직렬화한다.

- 현재 배포 인계: local/server-e2e-1107(f0b14c3 기반+로컬 변경), Nginx #67, 공간31, 생성기100명/30일·event_daily 집계 및 타이머. 실제 파일 지문·실행 사양·OpenAPI로 보완한다. 보드의 완료 시각19:30 표기와 19:08 관측 시각이 달라 문서 시각만으로 배포 완료를 판단하지 않는다.
- 부하: 정문 http://192.168.219.218, 예약 생성/모의 카드결제 201→본인 내역 GET→취소/환불200→확인. 검색·상세·slots GET을 포함한 사용자 여정이다. 읽기 전용10종과 같은 요청 분포는 아니다.
- 사전 준비: 단계별 전용 합성 계정100/200/400, 서로 겹치지 않는 미래400칸. 계정 공유·실제 계정 사용·completed 후기 fixture 생성은 하지 않는다. 비밀값은 메모리에만 둔다.
- 각 단계: spawn5명/초, 목표 VU 도달 뒤 warmup60초/measure180초/recovery120초, 생각 시간1~5초. 워밍업·drain/정리 포함 오류가 한 건이라도 있으면 다음 VU 중단. 오류율1% 미만이라도 그대로 증량하지 않는다.
- 기록: 요청별 JSONL, CSV/HTML, 정상201 금액/상태 검증, 트랜잭션 여정, VM7 CPU/RAM/디스크·I/O·swap·앱별 DB Sleep/Query/잠금·복제, 발생기/호스트, Nginx 안전 로그 및 upstream 필드, FastAPI 안전 로그·Uvicorn PID별 경고·HAProxy health, 타이머 실행 이력.
- 종료: 본인 합성 계정에서 소유·정확한 할당 칸이 일치하는 잔여 confirmed 예약만 API로 취소한다. DB 대량 삭제·스키마/연결 한도/VM사양 변경은 하지 않는다. SQL은 정합성 집계만 수집한다.
- 비교: 이전 읽기는 재배포 전1583778/공간19/Nginx구설정이다. 현재 쓰기와의 차이는 업무·배포·데이터 차이가 함께 포함돼 인과적인 최적화 효과로 해석하지 않는다. 신규 타이머도 끄지 않고 측정과 겹친 시각을 기록한다.

검증: 단일 오류에서도 증량 중단하는 판정은 실패 테스트 확인 후 구현, 전체 순수/격리10건 통과. 실제 예약201/취소200 smoke 통과 뒤 본 시험을 시작한다.
