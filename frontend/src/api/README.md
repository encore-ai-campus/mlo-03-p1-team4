# api — 백엔드 호출과 계약 목업

11-03 확정안 반영. 모든 서버 호출은 이 폴더를 거친다. 기준은 `docs/백엔드_A·B` 5절과 `docs/오류코드.md`다.

| 파일 | 역할 |
| --- | --- |
| client.js | Bearer·공통 X-Session-Id·오류 처리·401 알림. 관측 전송은 사용자 오류 알림에서 제외 |
| catalogApi.js | 유형·지역·NEW·메인용 조합 조회. 지역은 시도 목록, 시도 선택 후 시군구 조회 |
| venuesApi.js | 공간 검색·상세·시간 칸·예약 가능 날짜·시설 |
| reservationsApi.js | 결제 한 번으로 생성, 같은 요청 재전송, 충돌, 취소·내 예약 |
| authApi.js · usersApi.js | 가입·토큰 로그인, 내 정보·탈퇴. 로그인 뒤 getMe로 사용자 조회 |
| reviewsApi.js | 전체·공간별·내 후기, 작성·수정·삭제 |
| mock/catalog.js · mock/db.js | 생성 이름의 공간 10개, 실제 날짜 기준 테스트 데이터·회원·예약·후기 |

- `VITE_USE_MOCK=false`일 때 실제 API 호출. 기본은 브라우저 메모리 목업이고 새로고침하면 데이터와 목업 토큰이 초기화되어 다시 로그인한다.
- `/venues`, `venue_id`, 중첩 category·region, `image: art:…`, 페이지 목록 형태를 그대로 사용한다. 공간 카드에 서버가 제공하지 않는 주간 예약 건수를 만들어 표시하지 않는다.
- 결제 화면 진입은 쓰기 없음. `POST /reservations`에 method를 포함한다. 200과 201 모두 성공. 충돌은 `detail.slots`·`mine`으로 구분한다.
- 목업은 지난 예약 completed, 10분 내 동일 요청 재사용, 최소시간·인원·동의·14세·60분 토큰 만료·후기 기한을 검사한다. 실제 DB 동시성의 검증을 대체하지 않는다.
- `getHourlyUsage`는 명세에 API가 없어 메인에서 명시적으로 예시 데이터로 표시한다.
- 시연 충돌: 1번 공간 21시를 결제하면 다른 회원이 먼저 결제한 상황을 만들고 그 칸을 마감한다.
