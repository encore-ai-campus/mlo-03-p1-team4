# 다락큐브

**팀 방조**가 만드는 공간 대여 예약 서비스입니다.

> **다락큐브(多樂 Cube)**는 ‘많은 즐거움’을 뜻하는 다락(多樂)에 공간을 담는 큐브의 이미지를 더한 이름입니다. 누구나 원하는 공간을 찾고 이용하며 **모두가 즐거운 공간**을 만든다는 의미를 담고 있습니다.

## 프로젝트 소개

팀 방조는 스터디룸, 스튜디오, 카페, 강의실, 파티룸 등 다양한 공간을 검색하고 예약할 수 있는 공간 대여 웹 서비스를 개발합니다. **다락큐브(多樂 Cube)**는 ‘많은 즐거움’을 뜻하는 다락(多樂)에 공간을 담는 큐브의 이미지를 더한 이름으로, 누구나 원하는 공간을 찾고 이용하며 모두가 즐거운 공간을 만든다는 의미를 담고 있습니다.

회원은 공간 유형과 지역, 이용 조건에 따라 공간을 필터링하고, 상세 페이지에서 공간 정보와 이용 후기를 확인할 수 있습니다. 날짜와 시간대를 선택해 예약을 진행하고, 완료된 예약건에 후기를 남길 수 있습니다. 서비스는 회원, 공간, 예약, 결제, 후기 정보를 관리하며, 검색과 상세 페이지 탐색 등 주요 사용자 활동 로그도 수집합니다.

## 프로젝트 배경 및 필요성

온라인 서비스에서 사용자가 어떤 조건으로 상품을 찾고, 상세 정보를 살펴보며, 어떤 단계에서 예약을 이어 가거나 중단하는지 이해하려면 사용자 활동 데이터가 필요합니다. 팀 방조는 공간 대여를 온라인 상품 서비스의 사례로 삼아, 사용자의 탐색과 예약 과정에서 발생하는 활동 로그를 체계적으로 수집하고 향후 분석에 활용할 수 있는 데이터 기반을 마련하고자 합니다.

또한 공간 검색부터 예약·후기까지 이어지는 웹 서비스 흐름은 교육 과정에서 학습한 프론트엔드, 백엔드, 데이터베이스, 서버 구성 기술을 하나의 프로젝트로 연결해 적용하기에 적합합니다. 이에 따라 각 구성 요소를 역할에 맞게 설계하고 연동하며, 실제 서비스 구조에 가까운 프로젝트를 구현합니다.

## 프로젝트 목표

- 공간 검색, 상세 조회, 예약, 후기 작성으로 이어지는 사용자 중심 웹 서비스 구현
- 회원·공간·예약·후기 정보를 일관성 있게 관리하는 API와 데이터베이스 구성
- 공간 탐색과 예약 과정에서 발생하는 사용자 활동 로그를 수집하고 향후 분석할 수 있는 데이터 기반 마련
- 같은 공간의 같은 시간대에 동시에 요청이 들어와도 중복 예약을 방지하는 처리 구현
- 로그와 서비스 지표를 수집해 시스템의 동작 상태를 확인할 수 있는 구조 마련

## 주요 사용자와 기능

### 비회원

- 공간 유형과 지역별로 공간 검색
- 공간 상세 정보와 이용 후기 조회
- 회원가입

### 회원

- 로그인 및 내 정보 조회·수정
- 예약 가능한 날짜와 시간 확인
- 공간 예약 및 모의 결제
- 내 예약 확인 및 이용 시작 전 예약 취소
- 이용 완료 후 후기 작성·수정·삭제

## 예약 규칙

- 예약 단위는 객실이나 방이 아니라 공간 하나입니다.
- 예약은 1시간 단위이며, 공간의 최소 이용 시간부터 최대 4시간까지 연속으로 선택합니다.
- 예약 확정 시 예약, 예약 시간 칸, 모의 결제 기록을 하나의 트랜잭션으로 저장합니다.
- 같은 공간의 같은 시간 칸에 대한 중복 요청은 데이터베이스 제약으로 차단합니다.
- 예약 상태는 `confirmed`, `completed`, `cancelled`를 사용합니다.
- 이용 시작 전에는 예약을 취소할 수 있으며, 취소된 시간 칸은 다시 예약할 수 있습니다.
- 실제 결제 정보는 처리하지 않으며 결제수단은 모의 결제에만 사용합니다.
- 후기는 이용 완료된 예약에 대해 작성할 수 있습니다.

## 프로젝트 범위

**포함:** 회원, 공간 탐색·상세, 시간대 조회, 예약, 모의 결제, 예약 취소, 후기, 크롤링을 통한 공간 데이터 등록, 이벤트·서버 상태 관측.

**제외:** 실제 결제 연동, 호스트 공간 등록, 관리자 화면, 자유게시판·댓글, 예약 대기 및 결제 전 시간 홀딩, 모바일 앱.

## 기술 구성

| 구분 | 기술 및 역할 |
| --- | --- |
| 프론트엔드 | Vue 3, Vite, JavaScript — 웹 화면과 사용자 입력 처리 |
| 백엔드 | Python, FastAPI, SQLAlchemy — API와 업무 규칙 처리 |
| 관계형 데이터베이스 | MariaDB — 회원·공간·예약·결제·후기 데이터 |
| 비정형 데이터베이스 | MongoDB — 사용자 이벤트와 크롤링 원본 데이터 |
| 로그·지표 | Loki, Prometheus, Grafana — 로그 검색, 지표 수집 및 대시보드 |
| 개발 환경 | Python 3.12 conda 환경 `pro_1`, Node.js/npm |

## 시스템 구성 개요

```text
사용자 브라우저
      │
      ├── Vue 프론트엔드
      │       │
      │       └── FastAPI API
      │              ├── MariaDB: 회원·공간·예약·결제·후기
      │              ├── MongoDB: 이벤트·크롤링 원본
      │              └── 로그·지표: Loki·Prometheus·Grafana
      │
      └── 공간 검색, 예약, 결제, 후기 이용
```

MariaDB는 정합성이 중요한 서비스 데이터를 저장합니다. MongoDB는 구조가 다양한 이벤트와 크롤링 원본을 저장합니다. 예약 요청은 MariaDB 트랜잭션과 시간 칸의 중복 제약을 이용해 처리하도록 설계했습니다.

## 실행 방법

### 프론트엔드

현재 프론트엔드는 목업 데이터를 사용해 실행할 수 있습니다.

```bash
cd frontend
npm install
npm run dev
```

개발 서버는 기본적으로 `http://localhost:5173`에서 열립니다.

### 백엔드

백엔드 실행에는 프로젝트 conda 환경, 데이터베이스 구성, `backend/.env` 설정이 필요합니다. 준비 절차와 실행 명령은 [`backend/README.md`](backend/README.md)를 참고하세요. 비밀번호나 JWT 키 등 비밀값은 `.env`에만 두고 저장소에 올리지 않습니다.

## 현재 개발 현황

- 프론트엔드: 화면 7개와 목업 흐름이 있으며, 현재 화면은 이전 설계 기준이라 2026-11-03 확정안에 맞춘 변경이 남아 있습니다.
- 백엔드 A: 회원·후기·이벤트 등 코드 작성이 진행됐으며, 앱 실행과 실제 DB 연결은 아직 검증 전입니다.
- 백엔드 B: 공간·예약·결제 기능은 설계 문서 기준으로 구현을 진행할 예정입니다.
- 데이터베이스: MariaDB·MongoDB 초기 스키마 초안이 있으며, 실행 검증과 마이그레이션 반영이 남아 있습니다.

따라서 저장소의 일부 기능은 아직 구현 또는 파트 간 연동 전이며, 자세한 상태는 [`STATE.md`](STATE.md)에서 확인할 수 있습니다.
