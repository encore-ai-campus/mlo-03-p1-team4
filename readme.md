# 다락큐브

**팀 방조**가 만드는 공간 대여 예약 서비스입니다.

> **다락큐브(多樂 Cube)**는 ‘많은 즐거움’을 뜻하는 다락(多樂)에 공간을 담는 큐브의 이미지를 더한 이름입니다. 누구나 원하는 공간을 찾고 이용하며 **모두가 즐거운 공간**을 만든다는 의미를 담고 있습니다.

## 프로젝트 소개

팀 방조는 공간 대여 웹 서비스에서 실제로 발생할 수 있는 사용자 행동과 서비스 데이터를 체계적으로 수집하는 프로젝트를 진행합니다. 공간 검색과 예약이 가능한 웹사이트를 데이터 수집 환경으로 구현하고, 사용자가 어떤 조건으로 공간을 찾고 상세 정보를 살펴보며 예약을 진행하는지 기록해 향후 분석에 활용할 수 있는 데이터 기반을 마련합니다.

회원은 스터디룸, 스튜디오, 카페, 강의실, 파티룸을 유형·지역·이용 조건으로 검색하고, 공간 상세와 후기를 확인한 뒤 시간대를 선택해 모의 예약을 진행합니다. 이 과정에서 발생하는 데이터가 프로젝트의 핵심 수집 대상입니다.

## 프로젝트 배경 및 필요성

온라인 서비스에서는 사용자가 무엇을 검색하고 어떤 상세 정보를 확인하는지, 예약 과정의 어느 단계까지 진행하는지에 따라 서비스 개선 방향이 달라집니다. 따라서 실제 서비스에서 발생할 수 있는 탐색·선택·예약 데이터를 일정한 기준으로 수집하고 연결해 보는 과정이 필요합니다.

팀 방조는 공간 대여를 온라인 상품 서비스의 사례로 선택했습니다. 회원 정보, 공간 정보, 예약·결제 결과, 후기와 함께 검색 조건, 상세 조회, 날짜 조회, 시간대 선택, 예약 성공·충돌·취소와 같은 사용자 활동 로그를 수집합니다. 이를 통해 사용자의 탐색에서 예약 완료까지의 흐름과 이탈 지점을 살펴볼 수 있는 분석용 데이터를 축적하고자 합니다. 프로젝트는 교육 과정에서 학습한 프론트엔드·백엔드·데이터베이스·서버 기술을 활용해 이 데이터 수집 흐름을 구현합니다.

## 프로젝트 목표

- **수집 대상 정의:** 회원·공간·예약·결제·후기 데이터와 검색부터 예약까지의 사용자 행동 이벤트를 구분해 수집
- **행동 흐름 연결:** 비회원은 세션 ID, 로그인 회원은 세션 ID와 회원 ID를 활용해 여러 단계의 이벤트를 한 흐름으로 연결
- **수집 데이터 저장:** 서비스의 정형 데이터는 MariaDB에, 사용자 이벤트와 크롤링 원본은 MongoDB에 저장
- **분석 기반 마련:** 검색 조건, 공간 조회, 시간대 선택, 예약 성공·충돌·취소를 바탕으로 탐색·예약 전환과 이탈 흐름을 분석할 수 있도록 구성
- **데이터 신뢰성 확보:** 서버가 예약 결과 이벤트를 기록하고, 시연·생성 데이터는 실제 사용자 흐름과 구분해 관리

## 수집 데이터와 수집 방법

| 데이터 구분 | 수집 내용 | 수집 방법 및 저장 위치 |
| --- | --- | --- |
| 회원 데이터 | 회원 식별자와 가입·인증 관련 정보 | 회원 기능에서 생성·수정하고 MariaDB `users`에 저장 |
| 공간·예약 데이터 | 공간 유형·지역·시설, 예약 날짜·시간·인원·상태, 모의 결제 결과 | 공간 조회 및 예약 API 처리 과정에서 MariaDB에 저장 |
| 후기 데이터 | 예약에 연결된 별점과 후기 내용 | 이용 완료 후 후기 작성 시 MariaDB `reviews`에 저장 |
| 사용자 행동 이벤트 | 검색, 공간·날짜 조회, 시간대 선택, 예약 시도·성공·충돌·취소, 회원가입·로그인·후기 작성 | 프론트엔드가 이벤트를 묶어 `POST /events`로 전송하고, 예약 결과는 서버도 직접 기록 |
| 크롤링 원본 | 공간 데이터의 출처와 추출한 원본 항목 | 수집 작업에서 MongoDB `crawl_raw`에 보관하고, 정리한 공간 정보는 MariaDB에 등록 |

행동 이벤트는 `event_type`, 실제 수신 시각, 세션 ID, 선택적 회원 ID, 공간 ID, 공간 유형, 이벤트별 payload로 구성합니다. 검색 이벤트에는 검색어와 유형·지역·날짜·인원 같은 조건을, 시간대 선택에는 선택한 시간 정보를 담아 행동 맥락을 분석할 수 있도록 합니다. 이름·이메일·휴대폰 번호는 이벤트 payload에 넣지 않습니다.

수집하는 이벤트 유형은 `search`, `view_venue`, `view_dates`, `select_slot`, `reserve_try`, `reserve_ok`, `reserve_conflict`, `reserve_cancel`, `reserve_cancel_ok`, `review_create`, `login`, `signup`입니다. 프론트엔드에서 일어나는 탐색·입력 행동과 서버에서 확정되는 예약 결과를 함께 기록해 사용자 여정을 연결합니다.

프론트엔드는 검색부터 후기 작성까지의 이벤트를 최대 50건 단위로 전송합니다. 서버는 이벤트를 `events.log`에 먼저 기록해 Loki에서 운영 흐름을 확인할 수 있게 하고, MongoDB `user_events`에는 응답 뒤 저장해 분석 원천으로 활용합니다. 원천 이벤트는 365일 보관하며, 매일 이벤트 유형·공간별 집계를 MongoDB `event_daily`에 누적합니다. `select_slot` 이후 `reserve_ok`가 없는 세션 등 이탈은 별도 이벤트로 임의 기록하지 않고 이벤트 조합으로 계산합니다.

시연·생성 데이터는 `is_synthetic` 값으로 실제 사용자 흐름과 구분합니다. 이를 통해 분석 시 실제 활동과 검증용 데이터를 분리할 수 있습니다.

## 주요 사용자와 기능

### 비회원

- 공간 유형과 지역별로 공간 검색
- 공간 상세 정보와 이용 후기 조회
- 회원가입

### 회원

- 로그인 및 내 정보 조회·수정
- 예약 가능한 날짜와 시간 확인
- 공간 예약 및 모의 결제
- 내 예약 확인 및 이용 시작 전 예약 취소
- 이용 완료 후 후기 작성·수정·삭제

## 예약 규칙

- 예약 단위는 객실이나 방이 아니라 공간 하나입니다.
- 예약은 1시간 단위이며, 공간의 최소 이용 시간부터 최대 4시간까지 연속으로 선택합니다.
- 예약 확정 시 예약, 예약 시간 칸, 모의 결제 기록을 하나의 트랜잭션으로 저장합니다.
- 같은 공간의 같은 시간 칸에 대한 중복 요청은 데이터베이스 제약으로 차단합니다.
- 예약 상태는 `confirmed`, `completed`, `cancelled`를 사용합니다.
- 이용 시작 전에는 예약을 취소할 수 있으며, 취소된 시간 칸은 다시 예약할 수 있습니다.
- 실제 결제 정보는 처리하지 않으며 결제수단은 모의 결제에만 사용합니다.
- 후기는 이용 완료된 예약에 대해 작성할 수 있습니다.

## 프로젝트 범위

**포함:** 회원, 공간 탐색·상세, 시간대 조회, 예약, 모의 결제, 예약 취소, 후기, 크롤링을 통한 공간 데이터 등록, 이벤트·서버 상태 관측.

**제외:** 실제 결제 연동, 호스트 공간 등록, 관리자 화면, 자유게시판·댓글, 예약 대기 및 결제 전 시간 홀딩, 모바일 앱.

| 구분 | 기술 및 역할 |

| 개발 환경 | Python 3.12 conda 환경 `pro_1`, Node.js/npm |

## 시스템 구성 개요

```text
사용자 브라우저
      │
      ├── Vue 프론트엔드
      │       │
      │       └── FastAPI API
      │              ├── MariaDB: 회원·공간·예약·결제·후기
      │              ├── MongoDB: 이벤트·크롤링 원본
      │              └── 로그·지표: Loki·Prometheus·Grafana
      │
      └── 공간 검색, 예약, 결제, 후기 이용
```

MariaDB는 정합성이 중요한 서비스 데이터를 저장합니다. MongoDB는 구조가 다양한 이벤트와 크롤링 원본을 저장합니다. 예약 요청은 MariaDB 트랜잭션과 시간 칸의 중복 제약을 이용해 처리하도록 설계했습니다.

## 실행 방법

### 프론트엔드

현재 프론트엔드는 목업 데이터를 사용해 실행할 수 있습니다.

```bash
cd frontend
npm install
npm run dev
```

개발 서버는 기본적으로 `http://localhost:5173`에서 열립니다.

### 백엔드

백엔드 실행에는 프로젝트 conda 환경, 데이터베이스 구성, `backend/.env` 설정이 필요합니다. 준비 절차와 실행 명령은 [`backend/README.md`](backend/README.md)를 참고하세요. 비밀번호나 JWT 키 등 비밀값은 `.env`에만 두고 저장소에 올리지 않습니다.

## 현재 개발 현황

- 프론트엔드: 화면 7개와 목업 흐름이 있으며, 현재 화면은 이전 설계 기준이라 2026-11-03 확정안에 맞춘 변경이 남아 있습니다.
- 백엔드 A: 회원·후기·이벤트 등 코드 작성이 진행됐으며, 앱 실행과 실제 DB 연결은 아직 검증 전입니다.
- 백엔드 B: 공간·예약·결제 기능은 설계 문서 기준으로 구현을 진행할 예정입니다.
- 데이터베이스: MariaDB·MongoDB 초기 스키마 초안이 있으며, 실행 검증과 마이그레이션 반영이 남아 있습니다.

따라서 저장소의 일부 기능은 아직 구현 또는 파트 간 연동 전이며, 자세한 상태는 [`STATE.md`](STATE.md)에서 확인할 수 있습니다.
